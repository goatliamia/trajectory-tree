# 代码执行诊断

从原始代码、实际执行器与配对反馈定位失败层，再沿后续核对解决和任务结果。适用于命令执行与脚本运行，使用相同会话切点和原记录。

**先对齐执行链。** 分开宿主调度、脚本解析与参数绑定、程序运行、外部程序及其返回。按记录确认实际语言。嵌套执行时，结合外层与子进程各自的反馈确认错误来自哪一层、是否向外传播。


**把位置对回正确的代码。** 使用原始脚本和实际版本，区分脚本行列、生成的包装器位置、子程序堆栈和输出行号。PowerShell 按[专项方法](powershell.md)检查原始参数与解析器；渲染后的命令不能替代原始 argv。静态语法通过不代表运行时绑定、依赖、权限及任务效果均通过。来源截断时沿原文续读，历史代码只用于取证或静态解析。

**同一信号分别核对触发条件。** 一组 `NameError`、路径错误或退出码可能来自不同原因。与相近的成功记录比较，核对代码变化、环境与工作目录、实际可用能力以及当时收到的工具契约。缺少名字不能直接推导为需要安装依赖。遇到复合命令，保留先前已经生效的动作，定位真正失败的环节。

**沿实际结果收口。** 追踪改代码、换参、修配置、启用能力和跨轮处理，不用是否同参返回代替是否解决。明确影响的是临时辅助脚本、环境，还是原任务产物或验收。按[通用处置与知识保留](disposition.md)交付具体调整位置、理由、验证和保留选择；最终报告先完成主要调查。
