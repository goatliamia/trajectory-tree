诊断这次工作怎样取得结果、哪些投入有价值、哪些做法拖累了推进，以及下次先改什么。从用户指定的问题和范围出发，按需读取能支撑判断的运行证据。

Respond and write reports in the language of the user's current request unless they specify another language. Keep source quotations, paths, identifiers and tool arguments verbatim; the language of this skill or the logs does not set the report language.

## 从轨迹树或 Eval 的选区开始

从草稿的查询开始，保留其会话、切点和来源绑定；沿返回的续查入口读与问题有关的原文。选中多轮时对照关键转折，圈选多个调用时核对匹配范围。已有数据足以支持判断就直接分析，不为收齐各类指标补跑查询。历史图表的切点无法校验时重新取得选区。

按用户关注点串起行动、反馈和实际结果，引用关键记录。沿工具给出的计量口径使用数据；仅在覆盖缺口影响结论时说明。

## 综合诊断

**把任务、过程和结果放在一起。** 先确认用户要求的产物、关键约束和验收条件，再看实际交付及验证。按工作目的或关键状态变化划分阶段，例如定位、实现、验证、恢复；同一阶段可以跨多轮或包含子任务。区分需求变化带来的新增工作、任务本身的难度和可以避免的返工。模型说“已完成”与已有产物、验证结果分别核对。

**看投入怎样变成进展。** 对照阶段投入和关键转折：有没有获得决定性信息、排除路线、形成可用产物或完成必要验收。既找单次长阻塞，也找贯穿多轮的短等待、重复供给和恢复负担。把探索、准备和验证放回后续用途，判断它们是否减少了后面的风险或工作。

**从值得解释的现象追到可调整的原因。** 围绕同一个问题串起“当时掌握什么—采取什么动作—得到什么反馈—怎样处理—结果怎样”。从明显损失往前追，找到仍有机会改变后续的环节：前提缺失、工具选择或参数、反馈利用、状态交接、环境限制，还是验收太晚。结合当时已经可用的信息判断，不要求模型提前知道后来才暴露的事实。选择相近的成功尝试、前后阶段或不同对象作对照，检查解释能否同时说明它们的差异。

**选能改变下一次工作的建议。** 将宿主官方工具的语义、权限和保护机制作为固定约束。把建议落在可调整的调用方式、参数、工作流程、工作区约定或项目自有实现。交代改法的适用前提、预期减少的等待或返工，以及要保留的能力。优先考虑影响范围大、重复发生、改变成本低的环节。证据支持流程判断时可以先提出改法，精确收益交给验证。

**确定处置去向，再决定是否长期保留。** 按[处置与知识保留](references/disposition.md)决定修环境或实现、临时恢复、补齐能力和提炼经验。这是各类分析共用的方法，方向可以组合，错误类型不能直接决定处置。

涉及供给缺口、重复说明或过期知识时，按[上下文持续使用](references/context.md)核对当时实际可见的材料。当前配置由 `context-profile` 分析。

### 验证改法

回顾历史问题先沿已有后续核对解决与交付。验证新改法时，先明确应保持的任务结果和预期减少的负担，在原执行器、相关作用域及实际配置生效后检查原失败是否消失；诊断助手自己终端中的成功不能替代原执行链验收。涉及通用策略或能力配置时，再选正常任务和可能受损的边界、恢复场景作对照。能力补齐以原先做不了的动作能够完成为准。执行沿用用户授权和宿主权限；恢复前核对原操作已经产生的效果。检查完成质量，再比较完成时间、总用量、补读、返工或人工接手。单次成功用于确认这一例，普遍收益需要多例支持。

## 专项方法

只读取当前问题需要的方法；涉及多个因素时联合分析。

| 深入的问题 | 方法 |
| --- | --- |
| 时间被什么挡住，怎样更早取得结果 | [耗时与等待](references/latency.md) |
| 哪些投入持续增加开销，怎样保留能力地调整 | [用量与能力投入](references/cost.md) |
| 尝试有没有进展，反馈为何没有被用上 | [反复尝试](references/repeats.md) |
| 查找、读取、修改是否支持了正确判断 | [工具与文件使用](references/io.md) |
| PowerShell 命令为何报错，调用怎么改和验证 | [PowerShell 命令诊断](references/powershell.md) |
| 命令或脚本在哪层失败，后来解决了吗 | [代码执行诊断](references/code-execution.md) |
| 材料如何保留、更新和恢复，是否支持后续工作 | [上下文持续使用](references/context.md) |

需要交付报告时，按[报告写作](../../../../report/WRITING.md)组织。

通过 CLI 取证：将查询参数写入 `args.json`，用 Node 运行本目录相对路径 `../../../../scripts/trajectory-query.mjs --host codex --tool <工具名> --request <args.json>`。默认当前会话，指定会话加 `--thread ID`。工具声明用 `--tool schema` 获取。

需要 HTML 报告时读[组件用法](../../../../report/AUTHORING.md)；其中报告 CLI 位于本目录相对路径 `../../../../scripts/trajectory-report.mjs`。

草稿带有取证快照时，查询 CLI 使用 `--host codex --evidence "<快照路径>"`，保留草稿参数。快照固定了图中记录，不改用正在增长的会话文件。
