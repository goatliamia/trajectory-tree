# 报告写作

使用用户当前沟通的语言撰写正文、标题和图表说明；用户明确指定语言时以指定为准。不要因为本方法用中文书写，或被分析的日志是中文，就默认交付中文。保留引用原文、工具名、路径、参数、标识符和数据字段；如需解释原文，在引用之外补充译义。HTML 界面默认自动跟随宿主／浏览器，明确要求英文或中文时为报告渲染命令加 `--lang en` 或 `--lang zh-CN`。

Write prose, titles and figure captions in the language of the user's current request, unless they explicitly request another language. Preserve quoted evidence, paths, identifiers and tool arguments. Interface language is independent from the language of the source records.

报告是调查完成后的最终交付。写作前，模型先查清支撑主要判断的行动、反馈、后续处理和实际结果。正文直接交付结论与依据；只保留少量会影响判断、目前确实无法查明的事项，并说明它们影响哪项结论。调查中的补读、待查和对照计划留在工作过程。

先直接回答用户的问题，再用少量关键发现展开。把已经形成的判断、证据、动作与验证方式连成可读的叙述，讲清具体过程及其影响。原文位置放在相关发现或简短证据附录；任务内容用于解释投入，不按轮次复述项目。

历史报错先核对是否已经处理。已修复、验证或交付的工作写清结果，不再列为待办，也不要求为写报告重跑原任务。原文能识别的报错类型与造成任务负担的原因分别解释；核对临时脚本失误、反复出现的调用习惯、环境约束和项目实现问题。复合调用保留已经完成的动作，定位具体失败环节。归纳建议时交代适用场景、可调整的位置和预期减少的负担；零散且已经纠正的失误通常留在证据中。同参返回只是取证线索，改参、改脚本、换工具和跨轮的实际解决也应追踪。

使用能让读者采取行动的具体表述，不重复计量常识、通用免责声明和设计约束。只有证据缺口会改变结论或行动时，才说明具体影响。

围绕重要发现使用 Eval 数据。先用范围和轮次指标定位投入，再用工具、报错及请求表解释触发条件和后续处理。比较窗口或模型时，把样本数、已知结果分母和任务背景放在同一处。引用程序归因时保留确认程度，沿关键调用核对原文和实际产物。数据表里存在的指标由渲染器绑定，正文解释它们怎样影响任务和下一次做法。

按要表达的关系选图。一个整体中少量互斥类别的占比，优先使用扇形或环形图，例如不同窗口占用档位的请求构成，并显示总样本、数量和百分比。比较各档位的输出中位数等读数用条形图，随轮次变化用趋势图，表格用于核对明细或多项指标。一个分类维度可以同时展示构成与另一指标的比较，分别交代各自的分母；不把独立中位数拼成扇形图。
