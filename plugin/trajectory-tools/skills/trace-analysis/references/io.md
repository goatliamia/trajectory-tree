# 工具与文件使用

从下一项判断或修改需要的依据倒查工具操作。按实际获得的信息区分路径发现、匹配片段、正文窗口、完整结构与修改版本（`grep` 已返回目标片段时直接计入已取得证据）。

**沿“发现—取得—理解—使用—验证”定位缺口。** 检查目标是否被搜索范围覆盖、命中后是否取得关键邻近内容、是否读到当前版本、判断是否正确使用了证据，以及修改是否针对被观察的状态。

**检查重复操作的实际用途。** 对同一文件或对象，核对读取窗口、版本变化、修改前后和后续决策。区分“反复读取相同版本的同一片段 / 每次小窗口漏掉关键段落”与“修改后复查 / 跨阶段恢复背景”；优先调整搜索根目录、查询表达或读取窗口（一次完整读取足够决策时不拆成多轮小窗口补读）。

**分三类处理控制与策略拦截信号（`controls`）：**
- **文件观测与版本保护（`FS_NOT_OBSERVED` / `FS_STALE_VERSION`）**：若单次触发后紧接着补读并修改成功，按无需处置结案；若此前已读过（`priorRead`）仍反复触发，排查是否混用了非受控 shell 读取（如 `cat`/`Get-Content`）或经压缩/子代交接丢失了观测状态，出口指向改用宿主读取工具或在交接后先重读目标段落。
- **工作区隔离边界（`HOST_WORKTREE_GUARD` / worktree hook）**：核对会话所在隔离工作区路径与调用传入的目标路径。若后续已切回当前 worktree 路径完成修改，按边界正常生效结案；若仍受阻，出口指导将操作路径对齐到当前 worktree，保持共享主工作区不被改写。
- **审批拒绝或取消（`APPROVAL_REJECTED` / `APPROVAL_CANCELLED`）**：属于用户的显式控制决定。核对后续动作是否已遵从用户意图停止或改用合规方案；已遵从则无需处置。

验证关注是否更快取得足够证据、补读与返工是否减少、修改与验收是否通过。涉及工具供给或项目自有实现调整时，按[用量与能力投入](cost.md)评估。
