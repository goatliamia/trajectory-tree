# 处置与知识保留

从任务要求、实际原因及已有处理结果选择处置。能修掉的根因优先修掉，偶发事件恢复后不固化，能力缺少就补齐，值得复用的知识才进入长期指导。这些是通用的处置方向，同一问题可以组合使用。

## 将改进落到合适的位置

- **环境与实现问题。** 找到具体配置、程序路径、依赖或适配缺陷后，优先在对应作用域修根因。保留旧状态以便恢复，沿用户已有授权及宿主权限执行，在原先失败的执行链检查配置确实生效并恢复原任务。当前配置和适用版本随修复更新，旧绕过提醒相应失效。
- **偶发问题。** 按原操作已经产生的效果有限恢复并继续任务。读取失败与效果不明的写入分别处理。一次短暂失败通常不生成常驻规则；持续复现或出现明确环境证据时再调整判断。
- **能力暂缺。** 分开核对已安装、已加载、当前可调用和权限允许。优先利用已有能力；需要启用、修配置或接入新能力时，说明对象、来源与影响并沿授权处理。补齐以原先做不了的具体动作通过验收为准，用户未授予权限的要求仍保留未完成状态。
- **可复用经验与宿主知识。** 规则要能改变具体动作，说明适用条件、操作、依据和失效条件。也可从成功流程提炼方法。可变的版本、路径和能力优先由可刷新状态提供；工具契约由定义或适配层承载，项目约定与多步方法分别适合 `AGENTS.md` 和按需 Skill。尚未核实的反思只作候选。

遵循官方工具的公开契约和权限机制。修复可定位的配置、适配器或程序缺陷，与改写官方工具语义分别判断。建议本身不扩大授权，超出当前授权的操作先给出具体可审阅的变更。

## 留下知识前核对已有供给

按出错切点检查实际执行 Agent 已收到的 `AGENTS.md`、提示词、工具说明、已读材料及交接内容。事实缺少时补供给；过期、冲突或表达难用时修对应来源；已明确给出时分析调用如何与约束失配，避免追加同义提醒。磁盘上有文件不能证明当时已收到，报错也不能证明模型未收到或遗忘。按需用[上下文持续使用](context.md)追查。

## 交付什么

说明改哪里、为什么、怎样确认改对，以及是否值得长期保留。回顾历史问题先查已有解决与验收，避免把已完成工作重新列为待办。环境修复以原执行器生效为准，能力补齐以原验收动作完成为准，临时恢复以任务继续且副作用明确为准。修复记录、当前宿主事实和长期经验分别维护。
