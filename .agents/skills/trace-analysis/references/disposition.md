# 处置与知识保留

从任务要求、触发原因及后续处理结果出发，将诊断明确收口到以下五类出口（同一问题可组合使用）：

## 五类诊断出口与交付物

- **无需处置（直接结案）。** 当记录属于正常探测（如 `rg` 退出码 1 未命中、命令存在性检查）、触发保护或参数报错后在同轮立即修正且低成本通过验收、或用户主动拒绝/取消审批且 Agent 随后已顺从调整路线时，引用对应记录说明“属正常探测 / 单步已自愈 / 遵从用户控制，无遗留副作用”，直接结案，不强行拼凑改法。
- **修复环境与实现（`repair`）。** 定位到项目自有代码、脚本、工作区配置或运行环境的具体缺陷后，出口必须给出**具体文件路径与行号、最小修改方案（或经用户授权直接修改），以及在原执行器与原目录下的复跑验证命令**。**严禁修改宿主官方工具的源码、参数定义或内置工具说明**；官方工具的契约与保护机制作为固定边界遵循。
- **恢复与观察（`recover`）。** 针对超时、中断、结果未落盘（`TOOL_OUTCOME_UNKNOWN`）、文件观测保护（`FS_NOT_OBSERVED` / `FS_STALE_VERSION`）或工作区隔离拦截（`HOST_WORKTREE_GUARD` / worktree hook）：
  - 先核查目标文件、工作区或后台进程是否已产生半成品副作用；
  - 若后续记录已在合规路径下完成操作，按无需处置结案；若任务仍受阻，出口给出**符合保护契约的下一步安全调用**（如先调用宿主受控读取工具获取最新内容再修改，或将目标路径切回当前隔离工作区），偶发恢复不写入常驻规则。
- **启停或补齐能力（`capability`）。** 按“已加载但调用方式不对 → 已安装但当前配置未启用 → 权限/审批受限 → 缺少外部依赖”逐级排查：
  - 能由现有工具组合完成的，直接给出调用参数示例；
  - 涉及宿主官方或扩展工具的启停（开启或关闭）时，**Agent 必须先向用户阐述清楚该工具承担的核心职责、主流应用场景与低频兜底用途，在明确用户的真实任务需求后给出配置级启停建议（优先通过配置关闭不需要的工具，绝不篡改工具本身的语义）**；
  - 需要新装依赖或用户授权时，说明具体包名、作用域与验收动作。
- **保留可复用方法与整理供给（`knowledge`）。** 跨轮或跨会话重复出现同一具体调用约束失配，或验证了一套可复用的操作流程时，先按出错切点核对当时实际生效的 `AGENTS.md`、系统提示、工具说明与已读 Skill，再按性质路由到唯一落盘位置：
  - **短事实、目录边界与项目命令约定** → 交付 `AGENTS.md` 的具体修改草案（若已有条款过期、冲突或模糊，**直接改写或合并原条款**，不追加同义提醒）；
  - **多步专项操作规程与排障套路** → 沉淀到按需加载的 `SKILL.md` 或 `references/*.md`；
  - **项目自有工具的参数契约不清** → 转入 `repair` 更新该项目自有工具的定义（不动宿主官方工具）。

## 交付清单

每次诊断结论须明确：
1. **属于哪一出口**及支撑该判断的记录序号（`#seq`）；
2. **具体改哪里**（文件路径、配置项、能力开关或下一步调用命令）及原因；
3. **怎样验证改对**（原执行链复跑命令、预期产物与副作用检查）。已在历史记录中解决并验收的事项直接说明结果，不重列为待办。
