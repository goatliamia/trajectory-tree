# 代码执行诊断

从原始代码、实际执行器与配对反馈定位失败层，再沿后续记录核对解决状态与任务验收。适用于命令执行与脚本运行，使用相同会话切点和原记录。

**先对齐执行链。** 分开宿主调度、脚本解析与参数绑定、程序运行、外部子程序及其返回，按记录确认实际语言（PowerShell、Bash、Python、Node 等）。嵌套执行（如 `pwsh → ssh → bash`）时，结合外层与子进程各自的反馈定位错误发生层。

<!-- host:dsh -->
**DSH 代码模式。** PTC `run_code` 先读取原生运行时 kind，区分程序异常、预算到期、中止、运行环境退出和输出或协议约束；再结合子工具 dispatch 的各自返回定位具体失败点。

<!-- /host:dsh -->

**把报错位置对回源码。** 使用捕获的原始脚本（`command.source`）和报错帧（`codeFrames`），区分脚本行列、生成的包装器位置、子程序堆栈和输出行号。PowerShell 按[专项方法](powershell.md)核对原始参数与解析器；来源截断时用 `trajectory_read` 续读原文。

**比较触发条件并确定出口。** 对照相近的成功记录，核对代码差异、工作目录、环境变量与当时可用的工具契约；复合命令先确认前半段是否已产生磁盘或进程副作用。追踪后续改代码、换参或跨轮处理是否已通过原任务验收，按[通用处置与知识保留](disposition.md)收口到明确出口（已解决无需处置 / 修脚本或环境并在原执行器验证 / 安全恢复 / 更新 `AGENTS.md` 或 Skill）。
