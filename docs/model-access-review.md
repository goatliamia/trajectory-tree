# 模型取证入口：宿主审查与工具设计

2026-11-14。依据当前源码、本机安装目录、真实工具注册测试和 CLI 声明。这是现状与待实施设计，下面拟议的 `trajectory_profile` 尚未注册，不能让 Skill 提前调用它。

## 当前安装形式

| 宿主 | 实际入口 | MCP |
| --- | --- | --- |
| DSH | 原生 Cordis 四工具；`trajectory-query`、`trace-analysis`、`context-profile` 运行时 Skill；原生轨迹与 Eval 页面 | 不使用 |
| Pi | 原生扩展注册四工具、`/trajectory` 命令及两项分析 Skill；离线查询也可用 CLI | 不使用 |
| Claude Code | 插件内四个 Skill；SessionStart 提供 transcript 身份；模型用查询和出图 CLI | 不使用 |
| Codex | 本地插件内四个 Skill，加 stdio MCP 的四个取证工具和 `trajectory_view`；同包也有 CLI | 当前安装仍启用 |

本机三个便携包均为 0.2.5；方法资源逐文件一致，无 DSH 专属 PTC 文案。源码清单中仅视觉设计文档发生后续变化。分别执行三份安装目录里的 CLI，四个查询声明和独立命令诊断声明均可读。便携测试覆盖原生 Pi 注册、CLI 跨进程续读和来源绑定；DSH 实际 `apply()` 注册测试的 194 项断言通过。这不是对所有已启动宿主会话的热加载确认。

**之后采用的分发方向：DSH/Pi 保留原生工具，Codex/CC 使用插件中的 Skills + CLI，不默认启用 MCP。** 这次审查没有修改已安装的 MCP 连接。移除默认 MCP 分发时，应同步改打包依赖、view/eval Skill 的优先路径、安装缓存和传输验收，而非只删除一个配置文件。

## DSH 当前四工具

| 工具 | 实际职责与入口 |
| --- | --- |
| `trajectory_search` | `sessions / events / catalog / cost`：找会话、字面记录、类型目录和旧用量入口；events 默认排除注入与自身取证，可显式关闭 |
| `trajectory_inspect` | `overview / latency / cost / repeats / io / context`：会话统计、同参候选、工具文件及记录中的上下文；返回同切点快照和可继续调用的指针 |
| `trajectory_read` | 文本/JSON/关联记录、指定字段与长正文续读；用于追证据原文 |
| `trajectory_graph` | 记录替换/来源/派生关系及会话谱系；不是 HTML 出图工具 |

具体注册声明在 [index.js](../plugin/trajectory-tools/lib/index.js)，不把 DSH 与便携版本的参数混写。例如 DSH 的 `read` 使用 `format: linked`，便携 CLI 使用 `linked: true`；各宿主应按其真实 schema 生成后续指针。

这轮增强了错误归因、执行层识别、选区 `seqs`、日志身份与切点、长字段续读，以及工具计量/报错位置的底层投影。界面的四类处置矩阵和程序线索不等于又注册了诊断工具。`trajectory_command_diagnose` 已在便携 CLI 可用；它不是 DSH 的第五个原生工具，也没有默认注册为 Pi 的第五个工具。

## 已确认的缺口

1. **配置数据尚未形成直接查询入口。** 当前预设清单、来源、Skill 使用和文本重合由 `EvalWorkspaceService` 提供给页面。选区装填会写包含正文、哈希、来源和匹配依据的本地 JSON，模型可沿草稿读文件；四个会话工具不能直接请求这套当前配置。`inspect(view=context)` 不能被介绍成当前磁盘配置查询。
2. **自身声明漏采。** 当前静态扫描能识别 `ctx.tools.register({...})`，未识别本插件 `register({...})` 封装；配置采集又只列文件系统 Skill。已启用的取证插件实际注册四工具及三个运行时 Skill，却没有进入当前静态清单。页面现有总数只能说明已识别范围，不是完整运行时目录；不能直接把数字加四、加三冒充生效状态，还需处理预设过滤、同名优先级和停用策略。
3. **投影到查询返回有断点。** DSH 会话投影已有 `measure`、`codeFrames`，`buildInspection()` 复制调用时没有保留它们。便携普通 I/O 查询同样主要返回归因、状态与原文指针，未完整提供视图已有的计量/位置字段。模型仍可读原文，但它不能便捷复用页面的全部判断依据。
4. **方法发现仍偏被动。** `context-profile` 能消费页面生成的快照，但缺少不用先操作页面的紧凑配置摘要。Codex view/eval Skill 仍优先调用 MCP，与本次确认的 CLI 方向不一致。

## 工具边界

保留四个会话取证工具，先补齐现有 I/O 返回中的计量、原始诊断位置、执行层及依据。聚合查询保持精简，逐次调用才展开这些字段；原文继续走 `read`。处置方向提供可核对的线索和规则标识，不宣称已经找到根因，不据此自动停用或保存知识。

DSH 新增一个拟议的只读 **`trajectory_profile`**，负责“当前预设提供了什么”，对应 `context-profile` 方法。它与 `inspect` 的历史上下文分开，避免同一组 `session/cut` 参数突然代表磁盘配置。无需为 Skill、AGENTS、插件、注入和重合各建一个工具。

建议四个查询视图：

| 视图 | 默认返回 | 后续操作 |
| --- | --- | --- |
| `summary` | 解析后的预设与配置范围、使用范围、来源构成、可见性/覆盖、主要计量和少量值得查看的项目 | 返回带好参数的 `next` 指针 |
| `items` | 按类型/来源/名称选择的有限条目；体积、来源、加载阶段、使用与维护事实 | 游标翻页或读取具体项目 |
| `item` | 一项内容的文本、提供方、文件/注册位置、相关依据；长文本分段 | 沿 `nextRead` 续读，不复制整份配置 |
| `overlap` | 当前配置中的文本重合候选、覆盖比例、双方原句与共同加载条件 | 定位双方条目及原文；不输出“应删除”结论 |

默认参数只需能确定目标。会话内沿当前 Agent 的预设解析，离开会话时沿宿主默认预设；返回明确的实际解析结果。工作区省略表示预设全局配置，使用统计默认跨工作区近 7 天。只有用户指定项目时才加入项目指令/Skill，工作区和预设不相互绑定。自定义预设沿官方清单解析，名称歧义返回候选，不猜一个。

`snapshot` 固定配置修订和使用观察范围，后续页沿同一份快照。正文哈希或配置变化后，不把旧条目 ID 指到新正文。返回包区分：当前声明、运行时可见、已进入某次请求；缺少某一层就保留覆盖状态。动态注入没有触发时不填成零 tokens。

## 数据服务与开销

- 模型工具与 Eval 共用无界面依赖的取证服务、口径和缓存，不通过抓取页面或另起一个 MCP 服务取得数据。视图插件不应成为取证插件能否工作的条件。
- 对当前运行作用域，优先读取官方有效工具/Skill 目录及原生归属；配置声明用于补充来源和文件信息。其他预设的离线声明保持“待运行时确认”，不为了检查而激活用户插件。
- 修复自身漏采，应以原生目录和可校验声明为依据；静态扫描不是“已加载”的判据。运行时提供者也必须进入发现路径，而非只扫描磁盘目录。
- 初次只给紧凑摘要，原文、逐次调用与全部比较按需读取。使用已有会话投影和增量缓存；不在每次查询重新解码所有日志，也不下载向量模型。
- 分析查询只读。停用/恢复继续走现有管理流程和原生配置路径，不把配置写操作塞进摘要查询。

## 跨宿主与一键出图

同一套查询实现可以由原生扩展或一次 CLI 调用承载；传输方式不改变证据、分页和方法。Codex/CC 不需要为分析长期挂一个 MCP 进程。Pi 已能直接读取当前 SessionManager、工具目录和系统提示，保留这个原生入口比改成离线文件更完整。

DSH 的预设/插件配置能力不能直接套给其他宿主。Pi 可提供 SDK 当前配置；Codex/CC 的完整请求与加载项覆盖依宿主实际可读字段说明，不构造 DSH 的预设、插件或 PTC 概念。新版预设 Eval 总览仍只属于 DSH。

`context-profile` 是分析方法，`trajectory-view` 是确定性出图入口。用户可以用一句“分析当前上下文并打开轨迹图”组合两者，不必手写命令；Skill 本身不是图形组件。当前 Codex 对话可用：

```sh
node scripts/trajectory-view.mjs --host codex --serve --keep-alive
```

`--keep-alive` 是本次实测补上的 CLI 选项：生成结果后由同一进程保留预览服务，适用于会回收后台子进程的终端执行环境。调用方保留执行会话，服务仍沿用闲置和最长运行期限；必须验证返回的 URL 实际可打开。现有 0.2.5 安装包尚未包含这一新增选项。

来源取明确的 `CODEX_THREAD_ID`，不猜最近对话。会话 Eval 加 `--eval`，代码执行加 `--code`。生成本机 HTML 并打开链接，不调用模型；Codex 内完整系统请求未被记录的部分仍不能从图中还原。

## 职责与验收

常驻提示只保留入口与当前范围；工具提供数据和可执行的后续指针；`trace-analysis` / `context-profile` 放诊断与选择方法；文档保留口径、宿主边界和开发设计。不要把相同教程复制进工具简介、返回结果和每份 Skill。

实施顺序：修真实目录覆盖 → 补齐旧查询的字段 → 接通配置只读入口 → 更新各宿主 Skill 的发现与 CLI 路径 → 更新安装并验收。验收从模型入口出发：不用先点页面取得目标摘要、沿返回指针读到原文、切点和来源保持一致、生成当前对话图；再核对停用/自定义预设及不同工作区的范围。没有完成这些端到端路径前，不将“共用分析器已存在”报告为“各宿主功能已完整”。
