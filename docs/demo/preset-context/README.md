# Eval 页面源码与独立预览

页面已正式接入 DSH 左侧 Eval。此目录仍是页面源码；`scripts/sync-eval-workspace.mjs` 同步到安装包的 `lib/eval/workspace/`，原生服务实时读取 profile 和工作区，不依赖下方独立预览的 JSON。设计与验收见[正式接入审查](../../release-review.md)。

本地 DSH Eval 总览预览。以预设为入口，首页显示当前来源构成与使用表现；次级 Tab 为 Skill 管理、诊断、上下文窗口。展开查看当前指令文件、Skill、工具声明和系统／注入来源。当前版本不等于只剩清单：历史数据可提供使用背景，但不把旧正文或目录版本混入当前内容。

```powershell
node scripts/build-preset-context-demo.mjs --history --skip-trace
node scripts/build-eval-overview-demo.mjs
node scripts/build-current-preset-demo.mjs
node scripts/serve-preset-context-demo.mjs 0
node --test analyzers/preset-current-test.mjs analyzers/preset-context-test.mjs analyzers/preset-statistics-test.mjs analyzers/preset-provenance-test.mjs analyzers/preset-skill-management-test.mjs analyzers/skill-description-candidates-test.mjs analyzers/skill-window-test.mjs analyzers/eval-insights-test.mjs plugin/analysis-view/findings-test.mjs
```

默认读取用户的 web profile、当前工作目录及本地文件，支持 `--home`、`--cwd`、`--out`。产物写入 Git 忽略的 `.dsh/preset-context-demo/`。页面的“刷新配置”重新只读采集这些来源。

- **配置**：复用 DSH 的补丁解析与合并函数，避免启动宿主或改写 profile。只解析已知平台条件，其他动态条件保留待运行确认。
- **AGENTS.md**：使用官方指令发现器与加载预算，显示当前文件、截短情况和正文。
- **Skill**：使用官方文件系统 provider，关闭监听，按当前优先级去重；目录逐项展示，正文原位展开。
- **工具与注入**：读取当前配置对应的安装源码。普通元数据的 source 字段不算模型注入；只有消息构造入口和具名 context 注册进入相应清单。动态注册和实际请求组装尚未连接。
- **官方与用户来源**：`scripts/read-dsh-bundles.mjs` 直接调用本机 DSH `PluginManager.readBundles()` 的只读逻辑，使用原生 `official`、`availability`、包行与 preset 行归属。不给 manager 运行构造器，空 Loader 不产生实时激活记录。安装自带和官方扩展归 DSH 官方；profile 中用户安装的扩展归我的插件；AGMD 与个人／项目 Skill 按文件来源归我的内容。未知来源保留未知，不按命名空间猜测。名称、图标优先用原生本地化元数据，缺失显示名时仅格式化包名。
- **身份与系统提示**：官方 registry 构造器的 Harness 身份也纳入清单；预设身份前缀覆盖同名部署前缀，不重复计算。`complete` 预设只保留指定系统提示。界面明确区分身份前缀与组合后的完整系统提示。
- **体积与占比**：使用本机 DSH token 估算器。工具只计名称、描述与参数；Skill 只计目录，正文单列按需加载体积。AGMD 计当前文件正文，截短／省略情况另列。未解析内容为未知，不作为零；占比分母是已计量静态内容，不是完整请求开销。PTC 的声明计量不等于 SDK 组装体积。
- **使用背景**：读取本地历史投影 `data.json`，每个预设取最近最多 20 个已读会话，跨项目，只关联当前仍有的工具／Skill 名称。“未见使用”要求至少 3 个会话中有声明／目录可见且零次调用／加载；无可见证据（包括 PTC）归观察不足。名称关联不证明历史版本或效果相同。界面标明观察范围与历史采集时间。
- **样式与交互**：消费 `design/tokens.mjs`、`design/primitives.css` 与本地 Geist 字体。首页沿用用户选定的 A 拼装卡片与来源扇区，收起布局探索入口；旧 B/C 仅保留 URL `?layout=canvas|shelf&preset=cordis` 访问。默认入口 `?preset=cordis&tab=home`。先区分官方／用户插件／个人文件，再展开产品内容。类别来源沿用固定色；归属有独立文字与图形。共用侧栏详情保持总览位置，支持归属内分类、搜索、未使用筛选和当前正文展开。

`variants.js` 负责三种布局与展示投影，`controller.js` 负责共用导航和侧栏，`app.js` 保留正文阅读器；三版不复制采集或统计逻辑。

A 版在来源卡片上加入同色环形扇区：面积按当前已计量 token 分配，未知体积不进入面积；指针或键盘聚焦时扇区、读数与来源卡片联动，点击进入同一侧栏。产品类型的体积和使用统计继续保留在下方。

Skill 管理作为 Eval 的次级 Tab `?tab=skills`，仍沿用左侧预设。`preset-skill-management.mjs` 是自有分析模块，`skill-manager.js/css` 是共用数据上的管理视图，没有引入外部 Skill 管理项目、向量模型或向量数据库。

- 时效显示当前文件修改时间和实际读取事件的最后时间，仅作时间对照，不判为过期；同名历史关联不证明同版本。
- 历史投影保留每次成功 Skill 加载、手动唤起和正文读取的原始事件时间、session 与 seq。PTC start/result 不重复计数，失败调用不计为读取；旧投影缺时间时列为未计时，不借会话结束时间补日期。
- 调用图可选近 30 天、近 90 天或全部观察窗口，使用上海时区分桶，只展示当前同预设样本内已观测的事件。悬浮读数、点选日期、图例类型筛选联动 Skill 列表与可展开的原始会话／seq 记录；再次点选或清除恢复全量。方向键移动日期、Enter/Space 选择。详情里的单项图使用相同交互。未使用筛选仍要求样本中至少 3 个会话可见，不把缺证据当零使用。
- Description 检查在 `skill-description-candidates.mjs`：内置 Unicode 分词、词形／常见缩写归一化、稀疏词与短语特征进行候选检索；再要求同一任务动作附近的具体对象短语对齐、两侧覆盖充分，检查否定约束与 before/after 触发阶段。官方–官方不比较，明确正文引用视作配套关系并跳过。输出近似原文、职责候选或约束冲突，保留双方句子及对象／动作依据，不向用户展示“语义相似百分比”。没有 embedding、模型运行时、下载、远程请求或自动合并。
- 这是保守的规则检索，不是完整语义理解。动作归一化有有限词表，复杂语法、无共同表达的改写和跨语言关系可能漏检。测试覆盖正向改写／中文对象、不同动作、通用词、长套话、相反约束、不同触发阶段、官方排除与引用关系；这些样例不构成真实语料上的准确率承诺。当前 cordis 旧有 3 对弱提示全部不再列出，不降低阈值凑候选。
- 工具冗余检查只查当前可读工具描述／参数说明中至少 65 字符的规范化长句是否在 Skill 正文重复。工具名称引用不算冗余，无命中不代表完成语义审查。界面引用本机 Agent Experience 的“一项事实说明一次”，保留必要约束和工作流程。
- Skill、诊断和上下文窗口 Tab 的“刷新使用记录”串行刷新本地历史投影（跳过压缩轨迹页）、原 Eval 投影与当前配置；首页“刷新配置”保持轻量。两种刷新共享队列，避免同时改写数据。
- 诊断／窗口表现复用正式 `overview/data.mjs` 与 findings 的记录投影，页面由 `eval-views.js` 独立组织。`build-eval-overview-demo.mjs` 按同一批本地会话只读生成 `eval-data.json`；`eval-insights.mjs` 从原投影按预设、项目和时间切片，计算分档与证据；`/api/eval-view` 提供页面所需数据。预设按会话开场记录归类，中途切换未按轮次再拆分。不可解析的记录明确计入缺口，不代以零值。
- 主界面不再嵌入原总览 iframe。诊断保留反馈分类，以重复范围、识别依据、较早读取和后续返回组织；窗口按单个指标绘图，区间选择和对照在图旁边，详情使用共用视觉语言的抽屉。只在打开 Tab 时请求对应数据；筛选取消过期请求，刷新后重新取数。`render-eval-demo.mjs` 和旧 `/eval-retained.html` 仅保留作早期方案对照。

当前生成器是 `scripts/build-current-preset-demo.mjs`；配置语义在 `analyzers/preset-current.mjs`，统计在 `analyzers/preset-statistics.mjs`，源码静态字面量读取在 `analyzers/static-declaration.mjs`。先运行 `node scripts/build-preset-context-demo.mjs --history` 可刷新历史投影；没有该文件时仍能看当前内容，使用情况显示观察不足。“刷新配置”仅刷新当前文件和配置。

原轨迹压缩摘要试作保留在独立轨迹文件中，当前总览不提供压缩入口。此 Demo 尚未注册到正式 DSH 左侧栏。


## 本次判定核查与重排

- `FS_NOT_OBSERVED` 来自宿主错误码，表达工具保护条件未满足。近 30 天 cordis 的 27 条 edit 反馈均能在原始返回中核对到此码；19 条在同会话更早轮次有成功读取，22 条存在核实过的同轮同参后续非报错返回。因此标签调整为“文件保护要求先读取”，不等同于模型从未读取。
- `projectFindingCalls` 保留识别来源、原始错误码／返回摘录和更早成功读取的位置。读取记录不推定当时运行时的观测状态仍然存在。
- `summarizeFindings` 保持分类与配对规则；取消“跨轮重复且反馈已识别 ⇒ 保留方法”的自动建议，文件保护不默认引导修复实现。`causeConfirmed: false` 与 `needsAction: null` 分开保存，避免将类型识别当成根因或处置结论。
- 页面以字号、间距和细分隔线组织，取消外层卡片与重复跳转。参考 Geist Materials、Typography：低层级材料、明确文字角色，浮层再使用边界和阴影。
- Skill 改为读取趋势：点选日期只过滤列表，原始记录由显式入口展开；搜索与未使用筛选放在列表旁，不改变全局趋势。鼠标选择显示点和细参考线，键盘焦点显示点周围的小环，不使用 SVG 整列的浏览器焦点框。
- 常见说明收进“判定依据／统计口径”，页面正文保留当前结果、范围与操作。Skill 检查仍为有词表的规则检索，不宣称理解完整语义。


## 图表探索（Demo）

- Skill 管理取消内部图表 Tab。读取覆盖、未读取数量与文件更新横向组织，趋势图使用下一行；正文构成、重合检查和当前清单直接展开。覆盖按钮会原位列出所选 Skill、突出树图并筛选清单；零项按钮不提供无效点击。
- 正文矩形树图中，每个矩形只代表一个 Skill，面积按当前正文 token 分配；灰色表示零读取，蓝色色阶表示当前观察范围内的读取占比。使用接近方形的排布，小面积项改用编号与下方名称／体积／读取明细对应，极小项外置标号；不合并“其余”后与单项比较。正文体积不是每次请求的固定投入。
- 正文引用关系图已撤去。明确引用仍作为排除描述重合候选的依据，不改分析数据或原文。
- “修复实现、恢复观察、补齐能力、保留方法”直接作为处置矩阵的四个列头，计数与筛选合并在列头，不再另设一组四类卡片。沿用 `summarizeFindings` 的方向映射，保留文件保护与根因判定的区分。默认处置矩阵，数量对比与会话热图作辅助；URL `diag_layout=matrix|bars|heatmap`，辅助图使用紧凑方向筛选。流向图已移除。方向计数按当前范围的反馈组汇总，同一组可以关联多个方向；没有程序线索的方向提供主动核对入口。“保留方法”不因跨轮重复自动归入。所有单元格均可选择方向；详情可更换方向、补充关注点，草稿保留所选证据、专项方法和精确查询。列头计数仅表示程序线索。
- PowerShell：`projectFindingCalls` 从原始 DSH 事件读取命令和完整返回，按官方 pwsh renderer 的末尾标记保留非零退出、超时、停止与沙箱反馈。DSH 的命令非零退出通常仍是工具正常返回；这部分单列为命令反馈，不改宿主报错数、工具状态或窗口指标。普通正文引用的退出码不纳入，单独的退出码 1 保留未知或未命中候选。
- `enrichFindingPowerShell` 复用 CR `pwsh-observer`，每会话最多解析 12 项、2.5 秒预算，优先语法反馈与未定位记录。只把原脚本送入静态解析器，保留解析器版本、脚本摘要、语法位置与覆盖状态；不执行历史命令，不把解析器版本当成历史执行版本。可通过 `node scripts/serve-preset-context-demo.mjs 61738 --cr-root <CR 仓库>` 启动，刷新使用记录沿用相同配置。
- rc.2 的用户拒绝与审批取消、探测未命中进入“控制与探测”，不默认列为调查线索；原始记录和报错总数保留。审批服务、运行上下文、工具可调用性、输出契约与附件反馈分别提供分类依据；分类与处置结论分开。
- `diagnosis-review.js` 准备有界的诊断草稿：代表记录、来源会话与切点、原文查询、PowerShell / 代码执行 / 处置方法。补齐能力与保留方法进一步核对任务需要、已有能力、当时实际收到的 AGENTS.md / 工具定义 / Skill / 注入和后续验证。Demo 提供可编辑与复制草稿；正式宿主保留原生装填入口。没有向 DSH 草稿加入仅 portable 提供的 `trajectory_command_diagnose`。
- “诊断所选范围”可从当前预设、项目和时间范围发起调查，包括正常成功过程；不受自动分类限定。Skill review 扩展到完整上下文诊断仍需区分当前配置预览与历史实际供给，当前静态配置不充当历史已加载证据。
- 窗口默认“工具调用 / 工具报错占比”。主图以 0–100% 为正常量程；100% 进入最后一档，超出记录容量或负数的读数单独保留待核对，不裁到正常区间。曲线下方用等宽 5% 桶显示样本分布，并显示观测最高占用与中位数。
- 重合检查直接展示当前真实候选和三种演示摘要；选取演示再打开双方原文、命中依据与建议。`skill-overlap-demo.mjs` 的三组人工样例实际运行现有检查程序，覆盖触发重合、约束冲突、工具说明复述。只经 `/api/overlap-examples` 提供，不写入本地 Skill 清单、候选计数或使用统计，不使用虚构语义相似百分比。旧 `skill_view` 查询参数不再切换子页面。
- 这一轮按用户要求以视觉探索为主，不继续逐项细查交互。配色参考设计文档的内容／计量／状态分工，使用明快蓝、橙、紫、青；中性色留给辅助信息与未识别类别。

## 独立诊断判定

识别、四类处置线索与验收以 [诊断规则](../../diagnostic-rules.md) 为维护入口。`diagnostic-rules.mjs` 统一产出规则 ID、触发因素、证据与待查项，矩阵直接显示具体线索，详情与现有装填读取同一结果。重复出现本身不触发保留方法；具体共同约束或已有读取仍失配等因素可以形成保留方法候选。反馈身份、发生层和根因结论分别保留。装填与 Skill / 说明的去重审查后置。

## 加载项管理

Skill 的右侧抽屉汇总全部预设的使用情况，按预设逐行显示开关和读取次数；确认在原位展开。停用使用预设内的原生 Skill provider 覆盖，恢复移除此覆盖；不改共享 Skill 文件，也不创建正文副本。工具、插件使用同样的原位交互并明确实际范围与缓存提示。独立 Demo 保存配置，原生 preset generation 在新会话采用；运行态不作虚假完成承诺。研究出处、真实 registry 撤回测试和配置路径见 [加载项停用与生命周期核对](../../capability-management.md)。

操作前像、恢复信息及收据写入 `.dsh/preset-context-demo/management/`；不能发布该目录中的用户配置内容。读写接口仅在 loopback 使用，并要求同源凭据及一次性确认票据。
