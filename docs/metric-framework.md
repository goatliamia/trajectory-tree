# Trajectory Tree 指标框架

宿主记录提供事实。指标层在确定的范围内配对、分组、计算和标明缺失。Eval 取同一切点的事实与指标，结合用户的任务要求，判断实际效果、恢复和验收。面板可直接展示可复算的指标。需要判断任务含义时，再调用对应的 Eval 方法。

## 指标口径

每项指标记录对象、单位、来源、适用范围和计算式。按宿主保留会话或分支、记录切点及证据位置。比率附分子和分母。分母为零或测量证据缺失时返回空值，明确记录的零值照常显示。原生记录、程序派生和估算分别标注。分页与证据预览只改变返回体积，筛选和汇总读取同一批完整的可观测记录。

DSH 的步骤、Pi 的助手周期、Claude Code 的助手记录和 Codex 的可见动作有不同粒度。跨宿主可共用公式和结果形状，比较时还要核对采集范围和来源。 [宿主能力](host-compatibility.md)

| 领域 | 已有事实和指标 | Eval 如何转化 |
| --- | --- | --- |
| 执行时长 | DSH 提供官方步骤时长与实录步内工具区间。便携宿主保留原生 duration，在有配对起止和可用轮次边界时计算区间覆盖 | 结合依赖、等待和任务阶段解释耗时。相同的区间覆盖可以对应不同等待关系 |
| 用量与缓存 | 按宿主结算记录汇总已报告的 token 桶并提供字段覆盖。DSH 的缓存读取占比使用同一批成对记录 | 将投入放回实际推进、验证和交付判断。跨请求比较时核对用量桶与模型口径 |
| 工具执行 | 四宿主共用已返回、报错、未知的结果分布。结果覆盖率和已知结果报错占比分开 | 结合工具反馈、后续行动和状态复核，判断恢复质量与无推进重复 |
| 文件与信息 | 文件查询读取已有路径、操作和匹配片段。DSH 分组按调用与文件去重。便携宿主保留原生补丁和命令推断来源 | 关联读取、实际改动和同版本验收。判断返工、材料是否支持结论及实际副作用 |
| 任务与成果 | 已有用户要求、目标事件、产物、检查与结束状态。任务验收 Eval 已可在 DSH 冻结会话联调 | 按生效要求逐项标记已满足、未满足或待核验。工具返回、独立效果和最终交付各自留证 |
| 上下文、Skill 与协作 | DSH 有请求构成、投递和变更证据。其他宿主按可见历史、回执或委派元数据提供相应记录 | 核对关键信息是否送达并用于推进，以及子任务结果是否交接和验证。独立状态缺失时保留待核验 |

## 工具结果与文件关联

`trajectory_inspect` 的 `summary.toolOutcomes` 和 IO 表格的 `coverage.toolOutcomes` 使用同一口径。范围先应用轮次、对象聚焦和宿主自身的诊断调用排除规则，再计算分布。`outcome` 只筛选返回行，分页只选择当前页。

| 字段 | 计算口径 |
| --- | --- |
| `calls` | 范围内记录的调用或动作数 |
| `returned` / `errors` / `unknown` | 宿主适配后的非报错结果、报错结果、结果未知数量 |
| `known` | `returned + errors` |
| `outcomeCoverage` | `known / calls`，分母为零时为空 |
| `errorRate` | `errors / known`，分母为零时为空 |

结果覆盖率描述可见调用的结果状态。DSH 原生调用投影无法取得时，整项为空。Codex 的命令结束状态、可见输出和退出码分别来自记录。DSH 的一条 shell 返回可以包含多段检查结果。`returned` 支持确认工具返回，任务是否通过要核对具体检查及其对象。

文件分组使用调用已记录的全部文件关联。每组的调用数按调用计，同一次调用可以进入多个不同文件组。单条调用的 `files` 仍预览最多八项，聚焦文件优先放进预览，`omittedFiles` 标明省略数。宿主搜索本身截断的匹配结果按其上报范围读取。

研发 Eval 在同一日志切点只用实际交给 Agent 的调用与结果计算分布。隐藏自检结果时，该调用从已知变为未知。Eval 再按测试范围和实际返回判断该项验收。面板汇总、证据包和判定各自注明范围。 [运行方式](../experiments/README.md#任务验收-eval) · [DSH 字段口径](trajectory-fields.md)

## Eval 首屏的工具执行统计

| 指标 | 统计单位 | 口径 |
| --- | --- | --- |
| 调用与结果 | 当前范围内的一次轨迹调用 | 沿用工具结果口径，分为非报错返回、有报错记录、无结果记录。Code Mode 已有原生子调用时展开计数，包装器自身的报错仍保留 |
| 报错分类 | 一条有报错记录的调用 | 沿用轨迹树的错误分类。同一受阻段中的多次调用分别计数。调度前取消、执行中止和宿主报告结果未知各自列出。没有细分错误码时仍保留工具名 |
| 同参恢复 | 一条有报错记录的调用 | 沿用轨迹树配对。同轮、同工具且完整参数相同的后续调用有非报错返回时，为该条报错计一次同参恢复。同一个后续返回可以匹配多条较早的报错 |

会话统计覆盖轨迹树的整段会话，也可选最近 120 轮中的一轮。报错图按工具和错误类型汇总，并展示代表记录及对应的同参返回。工具耗时分布标注有配对时间的样本量。 [DSH 面板](../plugin/analysis-view/README.md) · [成熟框架对照](runtime-analysis-research.md#生产轨迹上的工具指标)

工具和文件分组的 IO 查询返回调用到结果的成对样本数、缺失数、覆盖率、累计耗时和 P50/P95。没有原生起点或结果的调用计入缺失。分位数只使用成对样本，单位为毫秒，并发区间可能重叠。原有逐步区间并集继续用于步内时间分析。

Eval 的「调用到结果的耗时」沿用这一口径，按所选会话或轮次分工具展示样本覆盖、累计值和 P50。至少有 20 个成对样本时显示 P95。每种工具最多列出三个最长的已测调用，可按调用及结果序号回查。

参数候选可在本地通过 `node scripts/inspect-session.mjs --source <会话日志> --view tool-checks` 计算。直接调用按当时记录的定义和本机 DSH 校验器核对，分列可校验、匹配、未匹配和未知。缺少内部定义的 Code Mode 子调用不计入可校验范围。三份冻结会话中的直接调用均通过此规则，区分度还需用更多真实案例核对。

## DSH Eval 的六类统计

面板在一次读取中固定日志切点，整段会话和最近 120 轮共用该切点。切换范围无需重读日志。点击带序号的样本可定位工具调用或所在轮次。样本预览有限，统计读取范围内全部可见记录。

| 领域 | 面板指标与边界 |
| --- | --- |
| 执行时长 | 轮次、步骤的实录起止；步内工具区间的累计与并集；DSH 官方统计重放的墙钟、首字、模型、解码、工具耗时、重试和报错。轮步累计取有边界的样本，官方字段各自附步骤覆盖 |
| 用量与缓存 | 按结算汇总未缓存输入、缓存读写、输出、推理和总量。各桶附上报记录数。缓存读取占比为同时上报 `cacheRead` 与 `input` 的记录中 `sum(cacheRead) / (sum(cacheRead) + sum(input))` |
| 工具执行 | 调用、错误类型、同参返回、时长分布和参数检查。相同工具与完整参数在同轮重复至少两次才计入候选组。后续返回与真实恢复分别核对 |
| 文件与信息 | 关联按调用、规范化文件路径和访问类型去重。对有起止且非报错写入的文件，分别统计在首次写入前已经返回的读取，以及末次写入返回后才发起并返回的读取。并行重叠和搜索命中不计为前读或读回 |
| 任务与成果 | 用户消息、轮次结束原因、目标变更、待办更新、工作区观测和交付登记。目标阶段取范围内最后记录，已清除的目标不计阶段。文件登记次数允许同一文件多次出现，交付验收需另核对产物和检查结果 |
| 上下文、Skill 与协作 | 请求头、上下文更新、投递回执、压缩及单列的压缩用量、裁短、Skill 目录和正文加载、子会话目录与交接消息。保留量指切点仍在宿主逻辑历史中的 Skill 加载结果。请求构成只用同切点的 `dsh-context` 可见分类记录，首末差和峰值只用分类完整的样本，与宿主压力及结算分开 |

没有测量的耗时、用量或投影显示为空。事件计数表示已观测到的数量。三份冻结会话已核对 5,978 次工具调用及其整段与单轮范围；最长样本保留一条缺失的调用结果。该样本的用量结算和请求构成记录覆盖不同，各自按实际来源报告。

## Eval 判定结果的汇总口径

研发侧 `experiments/corpus/eval-methods.mjs` 统一五种评价的结果分布。验收以生效要求、恢复以阻塞、重复以尝试组、副作用以实际状态变更、支撑以关键结论为计数单位。每项只计一个判定，证据不足记 `unknown`。覆盖率为已判定项除以本次提供的评价项数，没有评价项时为空；它不代表整个会话的覆盖率。

现有任务验收案例使用同一汇总口径。各方法的判据和校准案例见 [Eval 研究](runtime-analysis-research.md#第二部分-eval-指标与-agent-判断)。面板提供确定性指标，模型取证和判定留在后续阶段。
