# 上下文重合指标

第一版入口为 Eval → 诊断 → 加载项。Skill 管理和 Skill 详情链接到同一入口。页面先呈现相同原句、双方来源、加载位置与覆盖比例；原文对照在抽屉展开。当前只提供指标与证据，不生成合并、停用、删除或风险等级。选择依据另由后续文档／Skill 承担。

## 展示表达

参考 [Geist Colors](https://vercel.com/geist/colors) 对底色、组件状态和文本的区分，以及 [Materials](https://vercel.com/geist/materials) 对低层级表面与留白的处理。图形语义沿用项目设计语言。

- 每组使用完整横向空间：左边呈现两份具体内容，右边呈现共同原句与相同字符数。对象名、全文长度、加载位置同时可见。
- 比例条以各自全文为 100%。亮蓝表示相同文字，灰色表示其余原文；原文对照的高亮使用同一计量蓝。它们不表达风险、价值或停用建议。
- 内容类别通过小图标的既定来源色识别，官方／用户插件／个人内容继续使用来源标识；整块原文区域不按所有者染色。
- 标题旁显示对照组数，摘要说明匹配实际出现在哪类材料及哪个加载阶段。采集总量、来源分布与算法口径是次级信息，避免先呈现一屏登记数字。
- “展开原文对照”是明确的证据入口；图形与原句可以选择文本，不把整个内容块伪装为按钮。自主选择两项的入口固定在页面标题旁。
- 筛选按需展开；窄窗口保留对象与共同片段的关系，更窄时自然上下排列。详情抽屉复用同一比例图，不引入另一套读数表达。

## 数据与范围

[`context-overlap.mjs`](../analyzers/context-overlap.mjs)消费现有当前预设快照：系统提示片段、AGENTS.md、工具描述与参数说明、Skill 目录／正文、插件注入片段。插件归属沿用 DSH 清单与原生来源观察，不凭工具或 Skill 名字猜归属。注册与来源观察作为元数据，不另算一次内容。

每个文本字段记录来源、内容指纹及加载位置。按需 Skill 正文与开场配置分开；PTC 工具声明单列为工具目录，不假定整份工具定义已经进入请求。动态材料只比较读到的静态片段，截断／省略的项目指令不使用磁盘全文冒充实际带入内容。当前结果属于配置与本地内容层，未声称请求级共现，也不要求开启官方统计插件。

## 指标口径

- 只合并连续空白，保留大小写、标点、数字、操作符与否定词。
- 使用连续字符指纹与 winnowing 筛选位置，再逐字符验证并扩展完整相同片段。最短片段为 64 个规范化字符；不使用词语交集作为语义相似度。
- 覆盖比例为相同片段在该文本字段中的区间并集长度／字段总字符数。多个对象命中同一段不重复累计。总匹配量包含各份文本中的匹配部分，不是净多余量或可节省 token。
- “全文一致”指忽略空白后的全文相同；“包含相同文本”指一侧被完整覆盖；“局部相同”保留双方未重合的内容。
- 明确引用是附加信息，不排除整对文本。官方 Skill 之间不自动比较；手动对照仍能查看原文，并说明没有自动比对读数。
- 单份文本中同一指纹最多保留 64 个位置，避免高度重复正文导致候选位置平方增长。触发限制的文本 ID 留在 `method.limitedItems`，此时未检出不代表穷尽。当前四个真实预设均未触发该限制。

匹配位置保留原文偏移和文本行号，Unicode 与换行不同也能回到原文。摘要可以省略片段边缘孤立标点；详情高亮与数值使用未经裁剪的真实匹配范围。每组对照都能查看全文，也能主动选择未被程序列出的任意两项。

## 实现与验证

纯分析在 `analyzers/`；Demo 服务按快照文件修改时间缓存每个预设的结果；前端只渲染返回的数据。数据和算法不依赖页面组件或模型。2026-11-13 的本机样本：standard / cordis 各 208 个文本项，ptc 196 个，minimal 81 个，计算约 2–23 ms（不包括采集与页面渲染）。

[`context-overlap-test.mjs`](../analyzers/context-overlap-test.mjs)覆盖空白与前缀偏移、Unicode 原文定位、三份重复的区间去重、引用保留、官方 Skill 排除、否定条件不等价、加载阶段与重复文本预算。UI 已检查首屏原句、双侧高亮、手动对照、Skill 跳转。

上下文窗口的表现曲线与样本柱同时使用 0–100% 范围内每 5% 一档。点击任意一层选择相同区间；空档不连线，数值标签在悬停／选中时出现，100% 仍属于末档。
