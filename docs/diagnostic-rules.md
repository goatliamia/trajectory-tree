# 诊断识别、判定与信息规则

版本：v1，2026-11-13。适用于轨迹树、Eval 和当前上下文诊断。本文是识别与判定的维护入口；页面布局、装填编辑器和 Skill 正文分别维护。

**程序应直接在图上给出有依据的处置线索，并把依据与调查指南交给诊断。** 线索可以同时属于“修复实现、恢复观察、补齐能力、保留方法”。显示线索不要求先完成根因证明；最终改法、效果与长期保留再沿证据核对。

## 1. 本次复核发现的实施偏差

旧方法已经要求以尝试过程为诊断单位，结合任务、已有供给及后续结果选择处置。参见 [2026-10-30 方法复盘](archive/diagnostic-method-and-tools.md)、[处置与知识保留](../skill/trace-analysis/references/disposition.md)、[代码执行方法](../skill/trace-analysis/references/code-execution.md)。缺口主要在实现：

- 用“错误码 → 少量方向”的映射替代了过程判定，`knowledge` 没有正向候选规则。图上空列不能解释成没有值得保留的方法。
- 将反馈身份、原因认识程度和处理是否完成混在 `certainty` 中。结果明确未落盘，也被挤进普通“类型待识别”。
- pwsh 接上了退出标记和有限静态解析，但没有充分消费运行时 ErrorRecord、子程序诊断和执行层次。
- 未识别条目汇成一个大组，混合了尚未分析、格式未适配、反馈类型已知但原因未明、真实缺失结果。
- 把减少误判理解成少给线索。旧研究已经明确：限制推断的文字不能替代正面的比较方法和有理由的改进方向。

这不是旧记录整体不可分析，也不是需要先引入向量模型。部分属于确定的适配遗漏，部分需要把已有观察组织成更有用的线索。

## 3. 判定对象与输出

位置显示复用原生错误与现有解析观察，见[工具摘要与报错位置](tool-feedback.md)。文件／行列／原始原因与根因结论分开；PTC 代码自身、内部工具、远端程序各自定位。PowerShell 的包装行与 PTC Captured output 不代替实际报错源。

### 三种对象

1. **反馈记录**：一次调用及其配对返回。用于识别发生了什么、位置和执行层。
2. **尝试过程**：围绕同一对象或阻塞的行动、反馈、调整与验证。可以跨步、改参、换工具或跨轮；关系来源必须保留。
3. **上下文供给项**：当前预设下的一项指令、声明、目录、正文或注入，以及与它相关的实际任务表现。

按当前预设展示现状。历史记录用于使用与问题背景；比较时保留版本、执行器、项目及能力作用域，不能把不相容版本混成一种机制。同一错误码只是初始聚合条件，不能直接宣称同根因。

### 一份结果，共同供图与装填读取

| 字段 | 内容 |
| --- | --- |
| `source` | host、session、cut、调用 / 返回 seq、父调用、源摘要和相关版本 |
| `outcome` | 宿主状态、命令退出标记、子程序状态、任务验证分别保存 |
| `feedback` | 稳定身份、反馈类别、发生层、原文位置与识别依据 |
| `coverage` | 原文是否完整、是否解析、解析器版本、历史供给是否可还原 |
| `signals[]` | 方向、规则 ID、触发因素、证据、需核对因素和专项方法 |
| `followup` | 同参返回、改参处理、状态验证及其关联依据；缺失时具体标明 |
| `assessment` | 根因、建议、验证与保留决定的后续结论；不从 `signals` 自动升级 |

识别器输出可复用数据，不在图、草稿和 Skill 中各写一份分类规则。用户主动选择的方向单独记为关注点，不篡改程序证据或自动计数。

## 4. 反馈识别规则

先读原生身份和记录状态，再读与该调用绑定的运行时诊断，最后结合脚本结构细化位置和候选原因。外层与内层身份同时保留。

| 规则 | 触发证据 | 可直接显示的类别 / 信息 | 仍需核对 |
| --- | --- | --- | --- |
| F01 调用参数 | `INVALID_ARGS`、缺少必填项、参数 Schema 错误 | 调用参数不符合声明；缺哪个字段 | 当时声明是否可见、是否版本不匹配 |
| F02 工具与环境可用性 | `UNKNOWN_TOOL`、`TOOL_ACTIVATION_FAILED`、`TOOL_CONTEXT_UNAVAILABLE`、`APPROVAL_UNAVAILABLE`、原生插件不可用身份 | 注册、可调用性、运行上下文或审批服务分别显示 | 能力不存在、入口不对、未加载、服务失效分别调查 |
| F03 调用契约 | `INVALID_TOOL_OUTPUT`、`UNSUPPORTED_SCHEMA`、PTC 输出 / 协议身份 | 输出或适配契约问题 | 属于项目实现、插件还是宿主适配 |
| F04 文件与目标 | 文件不存在、非普通文件、替换目标不唯一、`ReplaceFileW` 反馈 | 目标 / 文件操作反馈 | 目录、版本、对象类型和具体操作结果 |
| F05 文件保护 | `FS_NOT_OBSERVED`、`FS_STALE_VERSION` | 保护条件未满足 / 文件版本变化；同时列早期读取 | 当时观测状态是否仍有效；不写“从未读取” |
| F06 PowerShell 语法 | 原生 ParserError / FQID、匹配解析器的 AST 诊断 | 语法身份、位置、执行器与版本 | 原脚本、包装器或嵌套字符串中的位置 |
| F07 运行时绑定与解析 | ErrorRecord 的 `PathNotFound`、`CommandNotFoundException`、`NamedParameterNotFound` 等 | 路径、命令解析、参数绑定分别显示 | 动作应在本地还是远端、实际 argv 与版本 |
| F08 子程序反馈 | Python traceback、Node 异常、编译器诊断、数据库错误、远端 shell 错误 | 程序身份、异常 / 诊断码及位置；保留 PowerShell 包装 | 辅助脚本、任务产物还是检查器出错 |
| F09 执行设施 | 沙箱准备、ACL 授权、临时环境或 worker 启动失败 | 宿主 / 运行设施失败；原生码和阶段 | 生效范围、权限与已有配置；不建议绕过策略 |
| F10 控制与后台任务 | 用户拒绝、审批取消、等待中止、job 不存在、子代理终止原因 | 用户决定、等待状态、任务身份和终止原因分别显示 | 操作是否已生效、是否仍运行、用户是否要求继续 |
| F11 结果缺失 | `TOOL_OUTCOME_UNKNOWN` 或配对结果未持久化 | 结果待核对；这是已知的记录状态 | 真实副作用与后续状态；不并入“反馈类型未知” |
| F12 输入与输出边界 | 附件类型 / 大小 / 格式、搜索输出溢出等稳定身份 | 输入条件或返回范围受限 | 调整请求范围、分页 / 续读入口、路由能力 |
| F13 探测与非零退出 | 已知探测命令、原始输出、退出状态及 AST | 明确未命中或未命中候选；否则显示退出非零、原因待查 | 外层 / 子程序状态、主动停止、原任务是否已得到答案 |

PowerShell ErrorRecord 识别须兼容 `Get-Content:` 与 `Get-Content :`、中英文输出及折行。优先提取 FQID、CategoryInfo 和位置，不靠某一句英文措辞。`NativeCommandError` 只是外部程序经 PowerShell 包装的反馈身份；继续读取内部诊断，不把所有 stderr 当作失败。

复合命令保留已完成部分。`pwsh → ssh → bash → node/python` 逐层定位；本地 `$(...)` 展开造成的命令解析问题不能直接变成“安装远端工具”的建议。返回是源文件、日志样本或测试预期错误时，不将其中出现的错误文字当成本调用的运行时错误。

## 5. 图上四类线索怎样产生

**以下是直接显示规则，不是自动修改规则。** 每个命中给出短标签、触发因素和代表记录；一组记录可以命中多列。判定没有覆盖的方向显示“尚未评估”，不能用 0 暗示已经检查且没有问题。

| 方向 / 规则 | 何时直接产生线索 | 图与详情提供的指南 | 最终建议需要补什么 |
| --- | --- | --- | --- |
| 修复实现 D-R1 | 参数、语法、契约、文件目标或程序诊断已定位 | 原始输入、错误位置、调用 / 程序 / 产物层次 | 找到可调整对象，在原执行链验证 |
| 修复实现 D-R2 | 同类服务 / 环境反馈在独立尝试中重复 | 触发条件、相关环境与已有处理 | 持续配置缺陷还是不同原因的相同现象 |
| 恢复观察 D-O1 | 中断、等待、结果缺失、保护、超时或临时访问反馈 | 原操作效果、后台状态、后续记录 | 是否需要继续，以及安全的恢复方式 |
| 恢复观察 D-O2 | 非零退出但具体原因仍未识别 | 原始返回、执行层、停止 / 探测因素 | 先定位状态，不默认重复执行整条复合命令 |
| 补齐能力 D-C1 | 明确的注册、加载、运行上下文、服务或命令解析缺口 | 已有能力、实际入口、当前作用域、版本和权限 | 区分补能力、启用已有能力、修环境和改调用位置 |
| 补齐能力 D-C2 | 任务需要的动作有证据，但已有能力难发现或未在需要的时刻可用 | 任务动作、目录 / 说明 / 加载记录及替代路径 | 哪个供给环节需要改善；不是默认安装插件 |
| 保留方法 D-K1 | 相同具体调用约束或执行机制在至少两个独立尝试中重现 | 共同身份 / 参数模式、相反或成功样本、当时已有指导 | 值得保留什么，是否已有同义说明，适用与失效条件 |
| 保留方法 D-K2 | 一次已验证的成功流程具有明确的可复用条件，或用户主动选取成功过程 | 操作顺序、前提、结果和验证入口 | 能否复现；放入原说明、项目约定还是按需 Skill |
| 保留方法 D-K3 | 已有读取 / 指导仍反复发生同一边界失配，或压缩 / 交接丢失继续工作的条件 | 已供给内容、失配位置、保留 / 丢失的具体信息 | 改供给组织、更新内容或补方法；避免再追加同义提醒 |

“独立尝试”需要不同轮次、不同已结束尝试或明确的调整起点；同一调用的多条状态、同一次并行分发和结果副本不增加次数。重复错误码不单独满足 D-K1，还需共同 FQID、同一缺失字段、同一约束或执行模式等具体因素。

D-K1 / D-K3 的显示不等待长期规则已经写好，也不要求先证明总收益。它们先成为“值得核对的保留方法线索”。建议写入长期指导时，才要求确认已有供给、实际有效的做法及范围。一次成功也可以进入 D-K2，不能把保留方法入口只绑定报错。

用户明确拒绝或取消的事实单独保留，不自动生成重试、修复权限或补能力的建议。它们仍可被用户选中诊断。文件保护默认提供恢复观察；早期读取和重复失配可以补充方法线索，不推定模型未读或忘记。

| 规则 | 触发信息 | 可显示的线索 |
| --- | --- | --- |
| C01 发现与加载 | 有相关任务需求，能力已登记但入口、描述或加载时机失配 | 补齐能力：先改善已有发现 / 加载路径 |
| C02 重复与冲突 | 同一事实重复、明确相反约束、同任务触发条件相互竞争 | 关联受影响对象及原句；提示合并 / 消歧调查，不自动删说明 |

当前概览只显示现版本配置，历史用于解释使用与效果。实际进入请求的证据不足时，照样可以展示配置 / 描述层面的线索，但不得将“磁盘存在”“目录可见”“读取过”混成“当时已经收到并采用”。官方 Skill 之间不列默认重合候选。工具语义、权限和保护机制作为既定约束；优先调整 AGENTS.md、发现入口、供给组织和项目自有实现。

当前 C02 的 Demo 实现为[上下文重合指标](context-overlap.md)：首屏呈现相同原句与双侧覆盖比例，保留来源、加载位置和引用关系。它只输出文本事实，不自动映射到处置方向或生成合并／停用建议；选择方法后续在文档和 Skill 中维护。

## 7. 未答与信息优先级

“待确认”必须说明待确认哪一层：

- **类型已知，原因待查**：保留具体身份和处置线索，例如路径不存在、等待中止。
- **执行反馈待解释**：已有非零退出或外部程序返回，尚未定位失败机制。
- **证据缺失**：缺原脚本、原返回、历史供给或状态验证；给出缺项及取证入口。
- **尚未分析**：解析预算未覆盖、处理队列未到；不能显示成判定无能或没有问题。
- **格式未支持**：已有原生字段或错误记录，识别器未适配；单列为实现覆盖缺口。

图首先呈现可采取下一步核对的线索；控制与探测另列，保持原始统计可回查。优先顺序综合未完成的阻塞 / 副作用、跨尝试的具体重复、受影响会话和工作投入，不只按报错次数排序。已在历史中解决的实例可进入方法保留，不重列为待修复任务。

每个方向至少交付：**为何显示、关联哪些记录、下一步核对什么**。短标签放图上，证据和方法展开查看。不要在每个单元格重复大段局限说明，也不以“用户可以自己选”替代程序已经能够给出的线索。

## 8. 接入与装填边界

识别保持在现有共用归因层；处置线索独立于图表渲染和提示词。`projectFindingCalls` 提供观察，`summarizeFindings` 聚合并调用处置规则，原生视图与 Demo 消费同一结果。

装填读取选区、`signals` 和原文入口，沿既有四个查询工具及 `trace-analysis` / `context-profile` 方法继续。DSH 不填入仅 portable 注册的命令工具。用户选择任意方向或整段成功过程均成立，不要求先命中程序规则。

**装填与 Skill、说明的重复风险留作功能完成后的专项审查。** 本阶段先完成识别、判定与信息供给，不扩写一套与 Skill 重复的长提示词；已有生成器只消费新的结构化线索。后续比较自动装填、方法正文和已有上下文三者的重复量、必要约束及整次诊断效果。

## 9. 验收与维护

| 验收案例 | 必须得到的回答 |
| --- | --- |
| 同一缺参错误跨尝试重复 | 参数类别 + 修复线索 + 方法候选；指出已有声明待核对 |
| `Get-Content :` / 中文 / 折行 ErrorRecord | 路径反馈可识别，不依赖英文冒号格式 |
| SSH 中出现本地 `pgrep` 解析错误 | 保留本地 / 远端执行层疑问，不直接建议安装 |
| Python / TS / SQLite 错误被 pwsh 包装 | 内层程序类别和外层状态并存 |
| git 进度或 npm notice 进入 stderr | 不仅凭 `NativeCommandError` 宣称产物失败 |
| AST 通过但运行时参数失败 | 语法通过与绑定错误同时成立 |
| 未进入解析批次 | 标为尚未解析，已有运行时身份仍参与分类 |
| 早期已读但触发文件保护 | 显示保护条件失配，不宣称从未读取 |
| 用户拒绝与审批服务不可用 | 前者保持用户决定；后者可显示能力 / 环境线索 |
| 改参或换工具后通过验证 | 可确认对应阻塞的后续结果，不受同参配对限制 |
| 重复但没有共同机制 | 保留重复现象，不自动触发方法保留 |
| 已验证的成功流程、没有报错 | 仍能形成方法候选并主动诊断 |
| 当前磁盘有说明、历史请求无记录 | 当前配置已知，历史供给仍待核对 |
| 多个方向同时命中 | 图、详情和装填收到同一组线索及规则 ID |
| 分类器未实现某个方向 | 显示未评估，不输出伪装成检查结果的 0 |

使用固定来源、切点和执行器版本回放；新增案例必须保留反例。分别验证反馈识别、处置候选、原文引用及建议收益，不能用前者通过证明后者有效。原始工具状态、调用数量、使用量与窗口指标不得随分类规则被重写。

对每个规则保存版本、正例、反例和具体证据来源。CR 的固定目标比较用于检查旧有回答是否保持、新缺口是否补回；不将有限回放的覆盖率当作全部真实会话的准确率。

维护时优先解决稳定身份和格式适配，再补执行层、过程关系及供给关联。原始私有日志、源摘要和逐条复核结果保存在 `.dsh/diagnostic-rules-review/`，不进入公开文档或包。
