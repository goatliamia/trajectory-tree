# Eval 正式接入与诊断装填审查

2026-11-14。范围：DSH rc3、Eval Demo 转正、诊断装填、重启缓存与便携宿主同步。本文记录本轮设计和验收，完成项以实际检查结果更新。

## 信息放在哪里

| 位置 | 负责什么 | 不重复携带什么 |
| --- | --- | --- |
| 用户生成的诊断草稿 | 用户问题、所选方向、范围、时间/版本、少量直接证据、可重查的定位 | 完整诊断教程、所有专项方法、未经选择的建议 |
| 工具定义与返回 | 用途、参数契约、作用域和切点；返回事实、覆盖情况和下一页/原文入口 | 对每项结果重复解释如何开展综合诊断 |
| `trace-analysis` | 从任务、行动、反馈与结果解释原因，决定改法并验证 | 当前磁盘配置、可变的版本或安装路径 |
| `context-profile` | 当前供给的职责、加载位置、重复与缺口；必要时沿使用记录深入 | 另一套报错分类或重复的通用处置教程 |
| Skill 引用资源 | 通用处置、上下文持续使用、PowerShell 等按问题读取的方法 | 每个入口各保存一份改写版本 |
| 文档 | 指标定义、设计理由、宿主能力、维护与验收 | 默认塞入每次诊断的上下文 |

保留两个不同诊断入口；通用处置只维护一份。执行反馈与加载项都使用同一种“选择范围 → 补充问题 → 预览草稿 → 填入/复制”的交互。程序分类提供调查线索，用户可以选择没有被程序归类的对象；草稿不自动发送，也不改变配置。

依据：本机 DSH rc3 的 `dsh-doc/references/tool-design.md`（原 Agent Experience），强调按需发现、关键约束在动作前出现、每项事实只说一次及衡量整个任务的开销。已有 `disposition.md`、`context.md` 保留解释与验证方法。文本相同指标只证明文字重复，不能替代职责、触发条件或任务结果判断。

## 转正时需要闭合的路径

- 原生左侧 Eval 入口直接提供首页、Skill、诊断与窗口，不依赖另起 Demo 服务器或预生成的本机 JSON。
- 当前配置先可读；默认使用预设全局配置，历史统计覆盖全部注册工作区并按会话逐步补齐。右上角统一选择工作区和今天 / 近 7 天 / 近 30 天，默认近 7 天。
- 配置读取、历史统计和诊断证据分别标注时间；加载失败有重试，刷新期间保留已有结果。
- 诊断草稿可以查看、编辑、复制；DSH 内选择目标对话后使用官方草稿接口填入，得到回执才显示成功。
- 加载项停用/恢复继续走官方配置与插件管理约束；确认在原抽屉内，说明预设范围及工具缓存影响。保存、运行生效分别按真实观察显示。
- 打包包含全部前后端依赖和字体。可安装包不得依赖仓库外研究文件、Demo 数据或固定用户路径。

## 缓存设计

原总览 `OverviewService` 的 `Map` 缓存在 DSH 重启时消失；首次访问会重新解码并投影每段日志。优先增加按会话版本保存的派生摘要，保持现有低优先级有界读取队列。原日志仍是权威来源。

跨重启复用要求：宿主/投影版本一致、相同会话与工作目录、持久化修订号一致；模型索引需要按保存的目录重新映射。活动会话的进程内序号不能单独作为跨重启键。失败和被取消的生产不能写成有效结果；缓存损坏或不可写时回退到原来源，不能让统计不可用。写入使用原子替换并限制数量与体积。

CR 的 `cache-transformation.md` 提供 `versioned-input` 目标、生产失败不覆盖旧结果及实际响应重放。KRT 的未来充分性提醒我们按后续查询保留必要身份和状态；此处用于摘要结构与失效条件，不把 KV 的数学结论当成本项目缓存正确性的证明。

当前 rc3 的 `dsh-session-projection-cache` 为 TypeScript 服务，通过宿主存储域持久化投影检查点；尚无证据表明总览应加入 C++ 缓存。是否需要原生计算由解码、投影和渲染的分项测量决定。

## 本轮验收记录

- DSH npm CLI 已由 `0.2.2-rc.2` 升级到 `0.2.2-rc.3`；CLI 版本、原生 PTY 子进程、34 项宿主消费者检查及 23 项指标/策略测试通过。已运行的宿主进程不等于已加载 rc3。
- npm 留下一个被旧进程占用的旧原生模块目录；未强删或终止用户进程。新版本原生 PTY 已正常运行。
- 正式 Eval 已接到原生 `/analysis-view/overview`，打包包含页面、采集器、管理接口及其依赖。原生路由检查页使用真实记录，验证了工作区选择、首页、上下文选区快照及 62 个目标对话的发现；本轮未向真实对话发送消息或停用能力。
- 20 个真实会话的冷投影约 4.3 秒；新服务实例从磁盘缓存恢复约 0.32 秒，原始日志读取 20 → 0，按模型身份归一后的结果一致。这是本机服务端回放，不是全部宿主启动耗时。
- 配置冷采集约 3.6 秒，重启后先返回最近快照约 13 毫秒，显示“正在核对配置”并后台重采集；管理预览仍等待最新读取。快照最多保留 4 个工作区 / 16 MiB。历史投影缓存限 1024 项 / 64 MiB，页面聚合另限 64 MiB，超出范围会明示。
- CR 全项目观察覆盖 200 个文件、6741 个执行单元；未观察到来源声明环。清理了 5 项失效导入及一个闲置局部绑定。其 1120 项“内部实现未供给”包含外部 API，不能当作 1120 个缺陷；`noLib` 引起的 13 项编译器覆盖提示也未当作运行时错误。
- 审查修复：重启缓存丢失、全局模型索引跨缓存失配、配置读取阻塞首屏、已生成样式但便携适配器未产出反馈字段、草稿只复制而没有原生回执、配置保存与运行应用混为一谈。具体程序线索的核对因素继续装填，通用教程改为 Skill 方法入口。
- 保留 12 条本机“目标插件条目不存在”的旧补丁诊断，未自动删除个人配置。真实归档中一段不可读日志继续标明未纳入，未填成零。
- Pi 1.5.2、Claude Code stable 2.1.311 和各自 Trajectory Tree 0.2.4 已实际安装/启用。Pi 官方资源加载器读取用户注册，四工具、命令、两 Skill 可见且 131 项源码哈希一致；CC 官方 details 确认四 Skill 与 SessionStart hook，实际目录和缓存共 1522 个文件哈希一致。没有调用模型。
- Codex 本地插件 0.2.4 已通过官方 CLI 安装启用，123 项源码哈希一致。真实 MCP 暴露四个取证工具和 `trajectory_view`，实际为当前对话生成了可打开的本机轨迹图；缺失会话 ID 的调用被拒绝。
- 五个实际 npm 归档通过独立解包：Codex/Pi/CC 的双语视图、查询切点、字体与 Skill 链接，以及 DSH 的原生元数据和页面资源。Codex 包排除了两项 SDK 依赖的公开测试目录，避免把不需要的夹具一起发行。

保留的兼容事项：Pi 提示 TypeBox 应为宿主 peer dependency。真实加载和工具探针通过；把它仅列为 peer 的实验会令 npm 归档丢失独立 CLI 依赖，因此当前保留完整依赖并记录提示。后续可分开原生扩展包与独立 CLI 发行物，不能为消除提示破坏现有入口。已有 DSH/Codex 进程需要重载或重新启动才能读取新的宿主/插件；本轮未中断用户运行中的对话。

## 转正后的使用记录回归

11 月 14 日核对正式宿主缓存：104 份摘要约 26 MiB，未触及 1024 项 / 64 MiB 上限；其中已有 Skill 读取事件。问题是历史分批到达后只更新了 `usage`，Skill 图表仍读取配置冷采集时生成的空 `skillManagement.events`，维护状态也未随最近读取更新。现将这部分派生数据与每次历史快照一起刷新，图表及修改状态直接读取最新 `usage`，复用静态描述检查；不增大缓存上限，也不要求重新扫描原始日志。

回归检查覆盖从零历史到首批、完整批次及清空范围后的图表与最近读取，并确认配置快照不被历史数据污染。单对话 Eval 已共用诊断规则，并在配置 CR 路径时使用同一 PowerShell 证据增强；其诊断草稿另补齐所选规则和核对因素，与总览装填保持一致。本机正式缓存中，额外静态解析目前仍有 `not-configured` 记录，不能将已接入口表述成已运行解析。

便携 Skill 审查发现 DSH 的 PTC / Code Mode 说明曾随共享正文复制到 Codex、Pi 和 Claude Code。通用方法已改为命令与脚本诊断；共享材料中的 `host:dsh` 段落仅生成到 DSH 分发，便携 Eval 入口同步去除 PTC 措辞。

本机便携插件已更新到 `0.2.5`。Codex、Claude Code 的安装缓存与 Pi 注册的本地包均逐文件核对 Skill 哈希，无 DSH 专属措辞残留；已运行会话中的插件上下文仍需在宿主重载后更新。

## 跨宿主范围

DSH 功能与代码审查完成后，使用用户指定的 GPT-6.1 Sol / high 子代更新本机 Pi、Claude Code 和项目适配，核对实际安装路径与生成包哈希。暂不移植新版 Eval 总览。Codex 优先本地插件和现有工具/Skill；可视化沿本机 HTML/浏览器入口，MCP UI 仅在宿主确实支持相应能力时启用，不把 ChatGPT 的 UI 支持推定为 Codex 的支持。


## 全工作区、预设开关与官方配置编辑

默认读取全部注册工作区；相同来源文件去重，同名不同文件保留来源选择。总量代表可用配置清单，不代表一次请求同时携带所有项目内容。重合比较排除只存在于不同工作区的文本对，文件维护状态按实际读取路径对应。

时间范围统一为北京时间的今天、近 7 天、近 30 天，默认 7 天。Skill 按事件时间，工具、诊断和窗口按记录轮次的时间筛选；不再额外截取最近 20 个会话。保留原有缓存上限和渐进加载，不重新迁移旧日志。未读取表示宿主会话读取或投影未成功，不等于没有 Skill 使用。

真实 19 个工作区的一次配置采集约 4.7 秒、序列化约 3.4 MiB，共享模块扫描不随工作区重复。配置快照最多 4 项、总计 64 MiB、单项 16 MiB；会话摘要和页面聚合的原有界限不变。Skill 作用域查询加停用预览由约 7.6 秒降至约 1.0–1.3 秒，只读测量没有改变用户开关。

发现并修复了配置写回缺陷：自写 YAML 编辑树把 `!!js` 解析为对象，但未正确表示该对象，修改后一个预设会把前一个预设的表达式输出成 `[object Object]`。操作前后备份确定了 6 处受损字段，包括 Skill 目录和平台条件；已逐字段恢复，其余文本、开关和注释保持原样。

正式预设修改已改用 rc3 的 `ctx.configEditor.edit()`，让官方 Cordis 路径管理锁、配置校验、表达式保留、Loader 应用与回滚。独立预览及宿主级 disabled 适配使用与官方一致的 YAML 标量处理，并由官方 Include schema 读取语义。

CR 的 `docs/pr-goal-ci.md`、`docs/source-goals-and-repair.md` 和 `docs/diagnosis-optimization.md` 给出了同输入目标比较与检查点覆盖方法。这里的开发目标是“修改选中项，未选项保持相同配置语义”，不能用文件写入成功或所选布尔值正确代替它。四个原生 YAML 回放交给 CR `compare-trial --goal-only`，旧实现未保持目标，修复后保持；官方编辑器另以真实隔离 profile 验证连续修改、表达式保留及失败回滚。未向启动流程增加审查界面或全量核对任务。
