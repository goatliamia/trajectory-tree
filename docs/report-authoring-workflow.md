# 从取证到一份可视化报告：写作与装配流程

状态：prepare/render 接口、Eval 同切点指标、CLI 及按需 skill 路由已接通。Codex、Pi、Claude Code 使用原生数据来源，DSH 使用连接文件。DSH 原生报告按钮尚未接通。组件、冻结数据采集和 MD → HTML 均由本仓库提供。

## 一份报告怎样组织

报告交付调查后的结论。主要判断涉及的后续处理和实际结果由模型在写作前核实，已完成的历史修复写清结果。建议围绕有证据的可复用改进；少量未查明事项单独说明其影响。按用户的问题和重要发现组织正文，图插在解释该发现的位置。

默认采用连续的单栏 Markdown。比较需要在一起的内容优先由 comparison、stacked、timeline 等组件内部协调；更多并排版式先经过完整报告试作，再作为少数稳定的布局能力提供。模型负责叙述次序和图文关系，渲染器负责文字大小、坐标、留白、图例、窄屏与打印。

## 建议的端到端流程

1. **分析。** 沿已有四个取证入口核对任务、失败原因、后续处理和实际结果。先完成主要判断所需的调查，区分已经处理的局部错误与仍值得保留的改进，保留会话、snapshot、范围及证据位置。
2. **准备数据。** 模型提交现有查询、Eval 表或已选结构切点；宿主沿同一日志身份冻结数据。Eval 复用页面的统计代码，提供范围、轮次、工具、报错、请求、模型和窗口分档。返回列、单位、覆盖及有界样本，完整数组由宿主管理。
3. **写报告。** 普通 Markdown 加 `report-figure` 声明。模型写标题、说明、字段绑定、记录 ID 与重点，不抄写数值数组，不生成图表 SVG 或 CSS。
4. **装配。** 入口检查数据引用、字段、单位和切点，调用 `renderReport` 生成单文件 HTML。绑定错误应定位到 Markdown 块和相关字段，让模型定点修正。
5. **阅读与修订。** 检查报告是否回答原问题、图是否帮助判断、行动是否可执行；检查完整页面中标题、长标签和图文节奏。普通报告先呈现静态结果，交互继续展开。

这不是要求额外调用五个工具。现有分析已完成就复用；已有冻结数据包就直接写作/装配。报告准备与渲染属于确定性操作，不为每种图新增模型工具，也不让模型往返搬运分页数据。

## Skill 里放多少

现有分析 skill 入口只增加生成 HTML 报告时的路由：

> 需要可视化诊断报告时，读取报告写作说明。沿用已取证的判断和数据范围，用普通 Markdown 与组件声明组织报告；颜色和排版由渲染器提供。

报告写作说明按需提供流程、组件的一行用途、数据绑定例子及准备/渲染命令。`trajectory-report.mjs components --type …` 从组件注册信息返回用途、绑定例子和必要说明；设计资产不常驻模型上下文。

| 组件 | 告诉模型的一行区别 |
|---|---|
| metrics | 提取少量关键读数，保留单位与来源 |
| bar | 比较轮次、工具等对象的数量大小 |
| histogram | 看耗时分布和长尾，选继续展开的范围 |
| scatter | 在两项可配对测量间找代表点或异常点 |
| timeline | 看有真实起止的调用怎样重叠或串行 |
| sequence | 把读过原文的行动、反馈和转折连起来 |
| context | 看来源构成怎样增长、减少及持续保留 |
| comparison | 对照两个明确时点，各项前后差在哪里 |
| donut | 看一个时点的互斥类别数量与比例 |
| stacked | 比较多个时点的数量或比例结构 |
| assembly | 用片段身份与逻辑顺序重放保留、追加和历史变化 |
| table | 同行核对样本、报错占比、耗时分位数和归因 |
| trend | 沿实际轮次对照同口径指标，空值保持断点 |

这里说明区别，完整字段约束由契约维护，避免在 skill、工具说明与组件文档重复抄写。来源数值不够画结构时，准备入口返回当前可用的数据和组件能力，不让模型自己补出拼装结构。

## 排版需要对模型说什么

三句话足够作为起点：

> 按发现组织章节，先给判断，再放支持它的图或原文。图前说明比较对象，图后解释对任务的意义及下一步行动。同一份信息不靠多种图重复铺陈；数量不由图种目录决定。

其余通过 [视觉语言与资产](../design/DESIGN.md) 和组件实现协调。模型可以选标题、重点和次序，不需要接触色值、字号、像素、动画时序或 DOM 布局。

## 指标怎样进入判断

先用范围指标交代规模，再沿轮次找集中投入，从工具和报错表回查关键记录。例如少量长调用占去多少累计工具时间、哪些报错已得到同参非报错返回、窗口分档内的输出和报错怎样分布。表格同时保留分母，趋势图帮助选择阶段。只展现对本次任务有用的组合。

模型和窗口统计沿用总览的请求配对规则。未明确配对到请求的工具结果保持空值；原生日志行号与轨迹序号分开保留。单个已记录模型仍可描述其请求分布，跨模型比较需要相近任务与充分样本。

图表行可展开关联记录，复制对应宿主的 `trajectory_read` 查询。选入报告的原文摘录可直接阅读，完整读数和来源另行展开。独立 HTML 保留字体许可并支持窄屏与打印。
