# 2026-11-16 代码扫描复核

本轮重新观察当前受版本管理的 JS / MJS 源码，替换 11 月 11 日的旧读数。固定范围、提交、模块图、复杂度分布与最高单元见[代码状态](code-status.md)。

## 范围与扫描链路

纳入 `analyzers`、`design`、`experiments`、`lib`、`plugin`、`report`、`scripts`、`skill`、`view`，以及正式 UI 的 `docs/demo/layout-review` 和 `docs/demo/preset-context`。测试文件、fixtures、依赖目录和构建输出不纳入该源码面；法则与验收 CLI 作为维护入口保留。

生成的轨迹资源、模型、Eval workspace 与当前上下文安装资源计入发行体量，排除出手写函数/文件排名。浏览器拼装片段的全局关系与宿主动态调用仍需要运行世界，不能从独立源码上下文推出它们不存在。

CR 先解析完整静态模块清单，再按消费者的所选静态 import/export 闭包分批观察。每批一次收集文件值依赖、未读绑定、未读导入、初始化调用与 rest 排除角色，不导出完整关系模型。初始整批运行触及原生观察器默认 4GB 上限，分批后完成；扫描只在显式运行维护脚本时发生。

修正了扫描器自身的三个问题：

- 旧源码面漏掉正式 UI 源码，现在一并观察。
- 旧缓存只依赖文件名单、引擎提交和未提交 diff；同路径的新提交可能命中旧图。现在校验实际源码字节、编译器、配置与收集脚本，分批缓存同样以来源哈希绑定上下文。
- 快照日期改为实际扫描日期，不再取最后一次提交的日期；相对引擎路径按调用目录解析。

## 旧摘要与解读接口的口径

`digest / interpret` 曾把连续调用写成冗余，把错误结果写成目标未达成，把缺少调用/消息记录写成未推进；客户端降级路径也存在同样结论。现统一到[共用观察模块](../plugin/analysis-view/lib/incident-facts.js)：

- 保留检测计数与证据序号，将必要性、任务结果和推进情况列为待核对。
- 错误与重复调用的关联使用明确的调用身份，取消相邻三个 seq 的推测。
- 缺少调用或助手消息的轮次提供轮次起点作为证据锚点，不判断整轮没有推进。
- 错误标记不能证明模型看到了哪些上下文，也不能证明 Harness 没有处理。
- 解读提示允许“无需进一步处置”，不强制形成实现改动。兼容字段 `severity` 用于信号排序，界面显示为信号权重。

V1 冻结输入与历史输出保持原样。迁移检查保留检测计数、类型与原始证据；不再要求新接口逐字重复旧的影响断言。新增回归直接检查必要轮询、换路径完成、未闭合/中止轮次、相邻无关错误，以及实际解读请求的提示与证据。形状、差分及迁移的 15 项变异均被检测到。

## 如何使用读数

`projectPresetContext`、`adaptPiSession` 和 Codex 事件分派仍是较复杂的维护点。圈复杂度描述分支结构，不能作为卡顿或无效工作的证明；本轮没有按数值机械拆分它们。

当前依赖数字是所选编译上下文中的文件值引用。指向 Node 内建库、宿主 SDK 或未纳入来源的模块请求，继续保留边界说明，不按缺陷数统计。程序调用名称的词法检查另行核对手写模块；真实宿主、浏览器和打包路径由对应回归验证。

复跑：

```sh
node scripts/code-status.mjs --engine ../code-relations --refresh
```

详细来源哈希、每批结果与复核记录保存在本机 `.dsh/code-status/`，不随包分发。
