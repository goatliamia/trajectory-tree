# Eval 首页：配置、来源与使用

首页面向想了解当前预设的用户，回答四个问题：有哪些内容、由谁提供、历史中用过多少、当前项目指令是什么。数据沿用当前预设快照与同预设历史；此次调整为视图层设计，不修改宿主配置或使用统计口径。

## 页面结构

1. **上下文构成。** 来源圆环与官方、用户插件、个人内容的说明放在同一区域。每个来源同时给出数量、具体例子、计量体积与占比，减少在图例与三张卡片之间来回寻找。未知体积不计入面积，待组装数量保留入口。
2. **使用覆盖。** 工具调用、Skill 正文读取各用一个半圆图。分母是当前配置中的项目数；同一观察范围内分为有使用记录、未见使用、记录不足三部分。蓝色表达有记录，灰色表达未见使用，斜纹表达记录不足，不使用风险阈值色。
3. **当前指令。** AGENTS.md 单独显示文件数量、体积、完整性、路径和少量正文标题摘录，不放进跨会话使用率的分组。没有配置时显示简洁空状态，不制造使用率读数。
4. **静态内容分布。** 通过一根按真实占比划分的堆叠条对比系统提示、指令、工具定义、Skill 目录与注入片段；下方标签保留数量和详情入口。系统提示词另有明确查看入口。

## 颜色、文字与交互

- 来源归属继续使用官方蓝、插件紫、个人青；内容类型保持项目已有来源色。使用状态色在两个覆盖图间保持一致，并同时提供名称和数量。
- 页面用留白和单层分隔组织，不给每个指标套一层边框。主要标签为 14–15px，次级信息 12px，计量值使用等宽数字；口径注释降一级。
- 来源圆环与说明行联动；点击分段或说明行查看该来源。使用图的非零分段、图例都打开对应状态的当前项目列表；零值只显示数值。详情有清除状态筛选入口。
- 宽屏将使用覆盖与当前指令并排；较窄窗口把当前指令移到独立一行。无 Skill、无指令、缺少历史记录与真正零使用分开表达。

三类使用状态互斥且覆盖所有当前项目。`used` 为存在调用／正文读取；`unused` 沿用至少 3 个可见会话且零调用的判定；其余为 `limited`。例如当前 PTC 的工具读数是 25 有记录、0 未见使用、31 记录不足，共 56 项；Skill 为 3、7、2，共 12 项。

## 参考与实现

参考了 Geist 的 [Typography](https://vercel.com/geist/typography)、[Grid](https://vercel.com/geist/grid)、[Entity](https://vercel.com/geist/entity)、[Description](https://vercel.com/geist/description)、[Materials](https://vercel.com/geist/materials)、[Gauge](https://vercel.com/geist/gauge) 与 [Empty State](https://vercel.com/geist/empty-state)。重点采用字体层级、内容与操作对齐、轻量分隔、显式比例标签和不同空状态的表达，不直接复制组件外观。

主实现为 [home-overview.js](demo/preset-context/home-overview.js) 与 [home-overview.css](demo/preset-context/home-overview.css)，由现有布局入口装配。使用状态划分同时供图形与详情筛选使用。四个真实预设的分段计数已经核对与原统计一致，并检查来源展开、状态筛选、键盘入口、宽窄屏及 minimal 空状态。
