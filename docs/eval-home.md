# Eval 首页：配置、来源与使用

首页面向想了解当前预设的用户，回答四个问题：有哪些内容、由谁提供、历史中用过多少、指令适用于哪些工作目录。默认展示预设全局配置，历史使用统计覆盖全部工作区并遵循右上角统一时间范围；选定工作区后，配置加入该项目内容，历史也切到该工作区。

## 页面结构

1. **上下文构成。** 来源圆环与官方、用户插件、个人内容的说明放在同一区域。每个来源同时给出数量、具体例子、计量体积与占比，减少在图例与三张卡片之间来回寻找。未知体积不计入面积，待组装数量保留入口。
2. **使用覆盖。** 工具调用、Skill 正文读取各用一个半圆图。分母是当前配置中的项目数；同一观察范围内分为有使用记录、未见使用、记录不足三部分。蓝色表达有记录，灰色表达未见使用，斜纹表达记录不足，不使用风险阈值色。
3. **指令来源。** 默认只展示当前预设使用的个人全局指令；选择工作区后，再展示该目录对应的项目指令。文件与正文可在抽屉查看，项目文件不并入全局圆环、矩形图或总量。
4. **静态内容分布。** 来源分区内直接拆到每项工具、每份指令文件、每条系统/环境片段和每项 Skill 的目录描述。多份 AGENTS.md 用相对路径区分，每项遵循当前选择的配置范围。外层按来源、内层按单项 tokens 分配面积，小来源安排在较宽区域，避免细长竖条；零值和待组装项不占面积。右侧先显示最大项及占比，指向或键盘聚焦任意小块即可查看完整名称、提供方和体积，点击直接打开那一项。点击来源名称可放大该来源的全部小块，再次点击或选“全部来源”恢复；占比仍明确使用总计量为分母。Skill 计量仍只算目录，正文不混入静态启动量。

## 颜色、文字与交互

- 来源归属继续使用官方蓝、插件紫、个人青，图标分别使用统一线宽的层叠、插头与文件符号，替换文字与加号。浅色底由前景色与当前页面底色混合，避免系统深色偏好把白色页面上的图标底染黑。
- 首页矩形树图采用直角方块、1px 窄缝拼合，来源之间保留轻量间隔；按来源使用蓝、青、紫的浅色填充，名称标注具体工具或来源文件，类型降为辅助标签。颜色不表达加载率或风险；Skill 正文图仍以蓝色深浅表示读取占比。两种图均明确写出自身编码。
- 页面用留白和单层分隔组织，不给每个指标套一层边框。主要标签为 14–15px，次级信息 12px，计量值使用等宽数字；口径注释降一级。
- 来源圆环与说明行联动；点击分段或说明行查看该来源。使用图的非零分段、图例都打开对应状态的当前项目列表；零值只显示数值。详情有清除状态筛选入口。个人和项目指令摘要直接筛选对应文件，抽屉可恢复全部来源。
- 宽屏以三个等宽内容列排列工具、Skill 与指令，标题、数字及底部入口使用共同的对齐线；统计说明独占下一行。较窄窗口把当前指令移到独立一行，说明仍紧跟使用覆盖。无 Skill、无指令、缺少历史记录与真正零使用分开表达。
- 预设切换位于左上角，与 Eval 标题并排保留一行直达按钮，按可用宽度收拢并始终保留当前预设；“全部预设”打开可搜索的导航浮层，支持任意自定义预设，不复用工作区/时间的表单样式；工作区、时间和刷新操作在右侧。移除页面内部第二层侧栏，嵌入 DSH 时沿用宿主的导航空间。

## 宿主主题

原生 iframe 读取 DSH 官方 `body[data-ds-dark-theme]` 的已解析主题，以及 `--dsw-alias-*` 颜色变量；主题切换时通过轻量 DOM 观察同步。浅深色以 DSH 为准，浏览器或 Codex 的 `prefers-color-scheme` 不再单独改变来源底色。独立预览默认浅色。

已用隔离宿主页验证“宿主浅色 / 浏览器深色”和“宿主深色 / 浏览器浅色”，包括原生下拉框的 color-scheme 与动态往返切换。主题测试复用已有 Playwright 依赖，见 [eval-host-test.mjs](../test/browser/eval-host-test.mjs)。

三类使用状态互斥且覆盖所有当前项目。`used` 为存在调用／正文读取；`unused` 沿用至少 3 个可见会话且零调用的判定；其余为 `limited`。例如当前 PTC 的工具读数是 25 有记录、0 未见使用、31 记录不足，共 56 项；Skill 为 3、7、2，共 12 项。

## DSH 指令加载与趋势选择

已核对本机 rc3 的 `dsh-agent-instructions` 官方实现与说明。挂载指令插件且文件系统提供者可用时，开局先加载 DSH home 与共享 agents home 的个人全局链，再加载从项目根到会话工作目录的项目链。默认以 `.git` 定位项目根，候选包含 AGENTS.md、CLAUDE.md 及 local overlay；同组相同正文会折叠，每条链按配置预算保留。成功 read、write 或 edit 到更深目录后，后续请求再补充适用指令；切换工作目录也会更新基线。

“全部工作区”是历史统计范围，配置对应预设的全局基础。采集器在这个范围不传项目 cwd；个人指令沿用官方发现、排序和预算，仅将项目候选列表置空。Skill 沿用官方 `FileSystemSkillProvider.list({cwd: undefined})`：保留已启用提供者的个人、宿主及显式自定义目录，不扫描项目根，也不把同名项目 Skill 的覆盖结果误当作全局内容。切到具体工作区才按官方优先级加入项目指令和项目 Skill。

工作区并非只影响 AGENTS.md。启用默认根的文件系统 Skill 提供者会按 cwd 发现项目 `.dsh/skills`、`.agents/skills`；禁用默认根或未挂载该提供者时，不能按目录存在猜测加载。显式写入预设的自定义目录即使位于某个项目里，也仍是该预设的配置项，不能按路径位置删掉。

此前把 1 份个人全局文件与 9 份项目文件合计成 17.0k tokens，是跨项目的来源清单，不是预设全局配置。已改为直接采集全局来源，圆环、矩形图、详情、Skill 清单和加载项诊断共用这个结果；缓存通过采集模块版本自动更新，历史统计缓存不失效。具体机制由 [官方提供者的隔离测试](../scripts/dsh-current-preset-test.mjs) 验证，包括项目同名覆盖与显式目录。

Skill 趋势悬停显示读数；点击日期筛选，再点同一日期恢复全部。图形空白、Escape 和“全部日期与类型”提供同一恢复操作。显式刷新使用记录清除日期、类型与临时覆盖选择，保留右上角时间范围及用户输入的搜索条件；后台数据更新保留当前选择。指针操作不强制转移焦点，键盘焦点恢复使用 `preventScroll`。

## 参考与实现

参考了 Geist 的 [Typography](https://vercel.com/geist/typography)、[Grid](https://vercel.com/geist/grid)、[Entity](https://vercel.com/geist/entity)、[Description](https://vercel.com/geist/description)、[Materials](https://vercel.com/geist/materials)、[Gauge](https://vercel.com/geist/gauge) 与 [Empty State](https://vercel.com/geist/empty-state)。重点采用字体层级、内容与操作对齐、轻量分隔、显式比例标签和不同空状态的表达，不直接复制组件外观。

主实现为 [home-overview.js](demo/preset-context/home-overview.js)、[home-composition.js](demo/preset-context/home-composition.js) 与 [home-overview.css](demo/preset-context/home-overview.css)，由现有布局入口装配。使用状态划分同时供图形与详情筛选使用。四个真实预设的分段计数已经核对与原统计一致，并检查来源展开、状态筛选、键盘入口、宽窄屏及 minimal 空状态。

插件在启动和后续步骤注入内容的实际核验见 [注入来源研究的 rc3 复核](injection-provenance-research.md#2026-11-14rc3-的真实插件核验)。静态分布图不把事件监听数量算作已加载内容。
